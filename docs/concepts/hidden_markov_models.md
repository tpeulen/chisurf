# Hidden Markov models of binned traces

A binned single-molecule trace — photon counts in consecutive time bins — rarely
looks like one process. It steps between levels: a molecule folds and unfolds, a
dye blinks, a complex binds and releases. A **hidden Markov model** (HMM) is the
standard way to say that formally, and to get from a noisy trace to states,
dwell times and rates without drawing thresholds by hand.

## The model

The trace is generated by a chain of hidden states $z_1 \dots z_T$ that cannot be
observed, and by an emission that can:

$$
P(z_1 = i) = \pi_i, \qquad
P(z_{t+1} = j \mid z_t = i) = A_{ij}, \qquad
P(x_t \mid z_t = i) = \mathcal{N}(x_t; \mu_i, \Sigma_i).
$$

Three assumptions are doing the work, and each is falsifiable on real data:

1. **Discreteness** — finitely many states. A continuum (a slowly drifting
   conformation) will be fitted as a ladder of spurious states.
2. **The Markov property** — where the system goes next depends only on where it
   is now, not on how long it has been there or how it arrived. This is what
   makes dwell times single exponentials.
3. **Gaussian emissions** — the counts in a bin scatter normally about the
   state's mean. For photon counting the truth is Poisson; the normal
   approximation is good once a bin holds a few tens of counts, and poor below
   that. Bin coarser rather than trusting a fit with three counts per bin.

$\Sigma_i$ can be an unrestricted matrix per state (`full`), a diagonal
(`diag`), a single variance (`spherical`) or shared between states (`tied`).
Fewer parameters fit more stably on short traces; `full` is what you want when
detection channels are correlated, as green and red are under FRET.

## Fitting: Baum-Welch

The parameters $(\pi, A, \mu, \Sigma)$ are estimated by maximum likelihood with
the **Baum-Welch** algorithm [^rabiner], an expectation-maximisation scheme:

* **E-step** — the forward-backward recursions give the probability of being in
  each state at each time, and the expected number of $i \to j$ transitions,
  given the current parameters. ChiSurf runs these in log space, so a trace of
  any length cannot underflow.
* **M-step** — re-estimate the parameters from those expectations. With the
  conjugate priors switched on, this is the MAP estimate of Huang et
  al. [^huang], which keeps a state that captured few bins from collapsing to
  zero width.

EM converges monotonically to a **local** optimum, so the starting point
matters. ChiSurf initialises from a k-means clustering of the bins, read as a
first hard-assignment guess at the state path: the cluster centres are the
means, the per-cluster scatter the covariances, and the transitions between
consecutive cluster labels the transition matrix. That uses the data — including
its time ordering — where the textbook random draw does not, and it converges in
markedly fewer steps ([benchmarks](../development/benchmarks.md)).

Where the states overlap, EM crawls: each step improves the likelihood by very
little while the optimum is still far away. **SQUAREM** [^squarem] extrapolates
the sequence of EM steps, jumping along the direction they are creeping in. It
reaches the same fixed point in a fraction of the maps and is on by default.

## Decoding: which state was the molecule in?

Fitting gives the parameters; **decoding** gives the path.

* **Viterbi** returns the single most probable *path* through all bins. It is
  self-consistent — the returned path has non-zero probability under the model —
  which is what dwell-time analysis requires.
* **Posterior (MAP)** decoding takes the most probable state in each bin
  independently. It can return a path the model itself considers impossible, by
  stringing together bins whose transition is forbidden.

Use Viterbi unless you specifically want per-bin marginals.

## How many states?

The likelihood always improves when a state is added, so it cannot answer this.
Use an information criterion, which charges for parameters:

$$
\mathrm{AIC} = -2\ln L + 2k, \qquad \mathrm{BIC} = -2\ln L + k \ln n
$$

with $k$ free parameters and $n$ time bins. Take the **minimum** — not the elbow
of the likelihood curve. BIC's penalty grows with the amount of data and
generally returns the smaller model, which is usually the one a kinetic
interpretation can carry. If the criterion keeps falling to the edge of the
range, suspect an assumption rather than a rich state structure: bleaching,
drift, or a continuum.

## Reading the result

**Dwell times.** For a Markov state with total exit rate $k_i$, dwell times are
exponential, $p(t) = k_i e^{-k_i t}$ — a straight line on a logarithmic
count axis. Curvature means the state is not one state: what is drawn as a
single level hides two with similar brightness. The mean dwell is
$\langle t \rangle = 1/k_i$.

**Rates.** Over a bin of width $\Delta t$ short compared with the dwelling,

$$
A \approx I + K\,\Delta t \quad\Longrightarrow\quad k_{ij} \approx A_{ij}/\Delta t
\;\; (i \neq j),
$$

which is how ChiSurf reports transition rates. The approximation fails once a
state turns over within a few bins — then $A_{ij}$ is no longer small, and the
rates are underestimated. Bin faster.

**Time resolution.** Nothing faster than one bin is visible, and a transition is
localised only to within a bin. Binning coarsely enough for the Gaussian
approximation while finely enough for the rates is the real experimental
trade-off in this analysis.

## When to use something else

| Situation | Better tool |
| --- | --- |
| Photons are sparse; you want rates faster than any sensible bin | **H2MM** — photon-by-photon, no binning ({ref}`concept-photon-by-photon-kinetics`) |
| Many short traces, each too short to fit alone | **ebFRET** — empirical Bayes shares a prior across traces ({ref}`concept-ebfret`) |
| States interconvert *within* a burst of a freely diffusing molecule | Gopich-Szabo photon-by-photon likelihood, or dynamic PDA |

## In ChiSurf

The estimator is {src}`chisurf/core/math/hmm.py#GaussianHMM`; the shared
analysis (state ordering, dwell times, model selection) is
`chisurf.plugins.core.hmm.core`, reachable from the GUI tool, the `csc hmm`
command line and the `hmm.fit` / `hmm.scan` RPC methods. See the guide
[Hidden Markov models of binned traces](../guides/54_hidden_markov_models.md).

For runnable code, `examples/notebooks/HMM_Binned_Traces.ipynb` (and its `.py`
cell-script twin) works through every point on this page against a simulated
trace with known rates: choosing the state count by BIC, decoding, dwell-time
exponentials, the short-bin rate approximation and where it breaks, and what
too many states looks like.

[^rabiner]: {cite}`rabiner1989` — the tutorial every HMM implementation is
    written against: forward-backward, Viterbi and Baum-Welch in one place.
[^huang]: {cite}`huang2001` — the scaled recursions in the form used here
    (pp. 443-445).
[^squarem]: {cite}`varadhan2008` — SQUAREM, the acceleration applied to the EM
    iteration.
