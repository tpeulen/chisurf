The imaging group reconstructs and analyses confocal (CLSM) TTTR images pixel-by-pixel:
intensity, mean arrival time, phasor-FLIM, lifetime (MLE) and number-and-brightness
maps, with calibration and PSF-determination steps. The plugins live under
`chisurf/plugins/microscopy/`; `imaging_common` holds shared base classes and
`imaging_tools` is the aggregating toolbox.

| Plugin dir | Display name | What it does |
| --- | --- | --- |
| `microscopy/clsm` | Imaging:CLSM-Draw | Build CLSM-TTTR image representations, pick pixels interactively, export decay histograms. Resolution estimation is **not** here: its FRC panel, RPC method and CLI command moved to `img_frc`, and the plugin's private forks of `counting_noise`/`gaussian_kernel` were dropped for the core ones. |
| `microscopy/img_pixel_intensity` | Imaging:Intensity | Per-pixel intensity map; writes the standard imaging HDF5 (with source back-reference) that later steps enrich. |
| `microscopy/img_pixel_micro_time` | Imaging:Mean Micro-Time | Per-pixel mean micro-time (arrival-time) maps. |
| `microscopy/img_pixel_phasor` | Imaging:Phasor-FLIM | Per-pixel phasor (g, s) maps and phasor plot. |
| `microscopy/img_pixel_mle` | Imaging:Lifetime:Pixel-wise MLE | Pixel-wise maximum-likelihood (2I*) lifetime fitting. Compute lives in the Qt-free `core/pixel_mle.py` (shared by GUI + RPC backend + CLI, headlessly testable) on the shared `fit2x` harness. GUI is an AutoForm `gui/pixel_mle.view.json` + Qt-free `gui/view_model.py` (`PixelMleViewModel`) + thin `gui/tool.py` (`ImgPixelMleTool`, a plain `QWidget` hosting `AutoForm`; runs `view_model.run()` on a `QThreadPool` worker) — the ~1900-line `imgmle.py`/`imgmle.ui` monolith wizard is retired. The view-model holds the transport-agnostic `api.models.PixelMleSettings` (same dataclass the RPC/CLI use), reuses `backend.services._build_irf_vv_vh` for IRF prep, and displays the fitted τ map through the shared `image` AutoForm section (`ImageMapWidget`: inferno colormap, per-file in-plot channel selector, frame z-slider). Exposes the `engine` (auto/fast/loop) + `n_workers` thread controls (also added to `api.models.PixelMleSettings` and threaded through the backend). Keeps the Imaging-Tools aggregator hooks `apply_setup_settings`/`apply_pipeline_context`/`apply_calibration`. Fast path: vectorised `CLSMImage.get_fluorescence_decay` extraction + threaded batch fits (tttrlib `DecayFit23::fit_matrix` fits a chunk of pixels in one GIL-released C++ call; threads over row-chunks via `fluorescence/mle/parallel.py`, no multiprocessing). Plus two tttrlib fit speedups: a Brent 1-D minimiser for the tau-only case (~4.9× faster fit, same minimum to 6 sig-figs) and hoisting the data-only signal integrals out of the objective (~10%). Cumulative ≈20× on the fit vs the original per-fit BFGS path; A/B-benchmarked with identical results. |
| `microscopy/sm_image_mle` | Imaging:Lifetime:Molecule-wise MLE | Molecule-wise MLE lifetime analysis from PTU imaging data: segments single molecules from the CLSM intensity image (watershed) and fits each by single-lifetime Poisson MLE (Fit23). Compute lives in the Qt-free `core/molecule_mle.py` (shared by an AutoForm GUI + RPC backend + CLI, headlessly testable against tttrlib-simulated CLSM images) on the shared `fit2x` harness (batch `fit_many` when curves aren't needed); the GUI browses molecules with the shared `image_browser` AutoForm section (per-molecule decay+fit plot), previews the segmentation before fitting, reopens a saved analysis from disk, integrates IRF/BG calibration + pipeline handoff, and exports the molecule table. Synthetic CLSM test images come from `core/fluorescence/imaging/simulate.py`. |
| `microscopy/img_pixel_nb` | Imaging:Number & Brightness | Per-pixel N and B maps. |
| `microscopy/img_coloc` | Imaging:Colocalization | Two-channel colocalization on **camera images and photon streams alike**: Pearson PCC, Manders MOC + split M1/M2, Costes automatic thresholds and block-scramble randomization significance, Li ICQ, Spearman, and van Steensel's shift profile. Coefficients live Qt-free in `core/fluorescence/imaging/colocalization.py`; image loading goes through the shared `core/fluorescence/imaging/image_source.py` seam (`load_image_stack` → `(frame, channel, y, x)` `ImageStack`, TIFF axis order read from the file, photon streams filled per routing channel / detector window). GUI is an AutoForm `gui/coloc.view.json` over a Qt-free `ColocViewModel` (settings dock beside tabbed coefficient table / channel maps / colocalized-pixel mask / intensity scatter / CCF plot), with the scatter gate driven by a draggable rectangle on the shared `image` section (`rect_roi_call`/`rect_roi_source`, `invert_y`). Workflow order matches the rest of the imaging stack — pick a detector setup (its named windows become the pickable channels before any file is read, via the new declarative `setup_selector` AutoForm section), load the image, pick the pair, set background/thresholds. Every control carries a tooltip and the `?` button opens the shipped `gui/help.md`. Two regimes: pixel-wise coefficients for continuous distributions, and **object-based** colocalization for punctate signal (segmentation + nearest-neighbour distances, coincident fraction within a resolution tolerance, centre-in-object fraction, per-object overlap) — the regime where correlation coefficients are dominated by the empty background between spots. Headless `img-coloc` CLI. Documented in theory ({doc}`concepts/colocalization`), application (guide 38) and as runnable examples (`examples/scripts/colocalization.py`, `examples/notebooks/Colocalization.ipynb`). Design: [PRD-67](/prds/prd-67.md). |
| `microscopy/img_drift` | Imaging:Drift Correction | Measure and remove inter-frame sample drift, in TIFF stacks and photon streams alike. FFT cross-correlation against a reference frame (first/previous/mean), the correlation smoothed before the peak search so a noise-driven tie between neighbouring pixels cannot flip the answer by a pixel; optional sub-pixel refinement and estimation restricted to a ROI. **Photon streams are corrected photon by photon** via `CLSMImage.transform`, so lifetimes, decays and correlations stay valid afterwards — shifting a rendered intensity image would discard them; a round-trip through an injected drift restores the image bit-for-bit with every photon conserved. Compute is Qt-free in `core/fluorescence/imaging/drift.py` over the shared image-source seam (shared with the image-correlation reader's own `drift_correction` setting); AutoForm GUI with the drift trace, before/after projections and the shift table; headless `img-drift` CLI. Documented in theory ({doc}`concepts/drift_correction`) and application (guide 43). Ported in spirit from the reference suite's MIA drift step. |
| `microscopy/img_frc` | Imaging:FRC Resolution | **What the photons actually resolved**, measured from the image itself — no bead, no calibration slide, no PSF model. Splits one acquisition into two statistically independent halves (even/odd frames, first/second half, two detector channels or two files), correlates them ring by ring in Fourier space and inverts the frequency at which the correlation falls through a threshold. The split *is* the measurement: correlating an image with itself gives 1 everywhere and a naive implementation would then claim single-pixel resolution, so every split here produces genuinely independent halves and "no crossing" is reported as an answer rather than as the last frequency of the axis. Three threshold conventions (fixed 1/7, ½-bit, 2σ), and **neither count-dependent one is uniformly stricter** — 2σ sits above 1/7 until a ring holds ~392 Fourier pixels and below it after, so the criterion is quoted with the number everywhere it appears. Compute is Qt-free in `core/fluorescence/imaging/frc.py` (rings binned on the *normalised* radius, so a non-square image is binned by physical frequency rather than by array index; rings past Nyquist dropped; count-based thresholds clipped at 1 and the saturated inner rings skipped). Full plugin stack: AutoForm GUI (`gui/frc.view.json` + `FrcViewModel`), `img_frc.*` RPC services with an in-process client the GUI and CLI share, and a headless `img-frc` CLI that exits non-zero when nothing crosses. Reads **TIFF stacks and photon streams alike** through the shared image-source seam; a `TIFF axis order` control covers the case that seam cannot guess (a short frame series labelled `SYX`, which would otherwise arrive as a one-frame multi-channel image). A panel of Image Tools after Drift — drift blurs the image, so an uncorrected stack measures the stage. Documented in theory ({doc}`concepts/frc_resolution`) and application (guide 51). |
| `microscopy/img_tracking` | Imaging:Particle Tracking | Single-particle tracking: **detect → link → analyse**, kept separate because each stage fails in its own way. Detection is the à-trous multiscale product (or a quantile threshold); linking is an **exact global assignment** (`scipy.optimize.linear_sum_assignment`) under a maximum step, plus gap closing with a √gap radius — linking had *no* prior art in this tree before this. Analysis fits `MSD = 4·D·τ^α + 4·σ²` over the short lags. Four things measurement forced: the **multiscale product** is required (one wavelet plane spreads a single-pixel spike, so min-area admits hot pixels, and false positives scaled with field area — 9.8/33.9/131.2 per frame at 3σ on 128²/256²/512² against 8 planted, versus 8.0/8.4/9.6 with the product); the noise scale must come from the **unclipped** planes (clipping zeroes the MAD and collapses the threshold to 1757 detections in a frame holding 8); error bars must be **bootstrapped over whole tracks** (the fit covariance assumes independent residuals, which MSD lags violate — it covered the truth in 4 runs of 20, resampling gives 20/20); and `D`/`α` are nearly degenerate, so `fix_alpha=1` is the default and `MsdFit.warnings()` speaks up when α is unresolved. Compute is Qt-free in `core/fluorescence/imaging/tracking.py` (with a **memory budget** on the movie simulator, since `n_frames·ny·nx·8` grows quietly) and orchestrated in `core.py`; AutoForm GUI with the movie plus detection markers, image-oriented trajectories, the MSD and a per-track table; headless `img-tracking` CLI (exits non-zero when no transport fit was possible) and two RPC methods. Also a panel of the Image Tools toolbox, **after Drift** — a drifting sample is indistinguishable from directed motion. Documented in theory ({doc}`concepts/particle_tracking`) and application (guide 50). |
| `microscopy/img_calibration` | Imaging:IRF & BG | Per-detector IRF and background calibration, shared with phasor and MLE steps (skippable pipeline step). |
| `microscopy/psf_determination` | Imaging:PSF Determination | 3D Gaussian PSF fitting and bead detection. Candidates are **regions**, not bright pixels: each sampled slice is thresholded, connected components are measured with `regionprops`, and the intensity-weighted centre of each spot seeds the fit. `min_area` is what separates a bead (several pixels) from a hot camera pixel (exactly one). |
| `microscopy/clsm_generator` | Imaging:Simulate:CLSM Generator | Generate a synthetic CLSM photon image from an intensity image + per-detector lifetime map(s) (TIFF/numpy) — ground-truth test data for the analysis tools. AutoForm GUI over `core/fluorescence/imaging/simulate.py::simulate_clsm_from_maps` (per-pixel emitters, lifetime×intensity quantised into species per channel); browses input maps + reconstruction in the shared `image_browser` and saves the photon stream (.npz/.ptu/.spc/.ht3) + intensity TIFF. |
| `microscopy/imaging_tools` | Spectroscopy:Image Tools | Unified toolbox: Setup, Image Browser, **Drift Correction**, **Resolution** (FRC), Particle Tracking, the numbered per-pixel steps, molecule/pixel-wise MLE, CLSM Draw, PSF Determination. The order encodes the workflow: Drift sits between Browser and the numbered steps because every per-pixel map below is built from frames that must already be aligned, and Resolution sits directly after it for the same reason — drift blurs the image, so an uncorrected stack measures the stage rather than the microscope. Acquisition *planning* is deliberately not here — the RICS-precision predictor consumes no dataset, so it lives with the [calculators](calculator.md) rather than in a pipeline whose Back/Next walk threads one dataset through the numbered steps. |

These plugins form a pipeline: an HDF5 with a source back-reference is created once
(intensity), then N&B / phasor / MLE steps enrich it, with calibration transferred
between steps. Discovery, activation and declarative panels follow the standard
contract ([plugin system](/architecture/plugin-system.md),
[Plugins target](/specs/plugins.md), [GUI & AutoForm](/subsystems/gui-autoform.md));
AutoForm's `image`/`waterfall` sections drive the 3D-stack viewers and pixel picking.
The per-pixel CLSM pipeline runs compute in a non-blocking worker process. Correlation
imaging is a fitting experiment rather than a plugin: one spatiotemporal correlation
carpet covers RICS, STICS, TICS and iMSD, described in
[image-correlation theory](/references/image-correlation-theory.md).
Design context: [PRD-51](/prds/prd-51.md), [PRD-52](/prds/prd-52.md) and
[PRD-67](/prds/prd-67.md) (colocalization + the shared image-source seam that lets
imaging tools read camera image stacks, not only photon streams).
