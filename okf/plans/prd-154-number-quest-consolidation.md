# Number Quest canonical module consolidation

## Cleanup plan before code

The approved P-F9 direction retains the richer committed root app and drawing
implementation under gui/, then removes the obsolete alternate surface. Capture
that canonical app in a deterministic realistic round before any source edit.
Control inventory, numeric state, default dimensions, locale and full rendering
commands are the acceptance reference; no pixel threshold substitutes for controls.

One owner writes both ends and all direct consumers. Update relative core and
translation imports, resource paths, manifest and games/gui/registry.py, capture
helpers and source/tests. Preserve NumberQuest translation context,560×420 default,
primary numeric declaration, complete saved round/resize, held repeat/release,
optional audio lifecycle, plot dialing and submit/reset controls. No compatibility
alias for the obsolete target= constructor or old A/D repeat behavior.

## Shared-tree preservation

Save byte-exact before copies and foreign diffs before overwrite. Root app has
uncommitted semantic key changes; transfer them to the migrated working GUI as
unstaged changes, never into the committed migration candidate. Registry semantic
key-description changes remain unstaged while only its module path changes land.
The obsolete GUI/drawing formatting edits are AST-identical; preserve their before
copies and formatting intent in the working migrated files. Do not run destructive
git or delete dirty root files from disk. Retire their committed paths in the index
only and leave the original dirty sources on disk for explicit owner handoff.
Exact HEAD-plus-owned GUI candidates exclude all foreign changes. Record the
remaining local files/patch paths in the owning resume so no work vanishes silently.
