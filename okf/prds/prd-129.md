# Correlator batching

# Why

Two register rows on one engine surface. fFCS
(`species_filtered_correlation`) walks the same photon stream n(n+1)/2
times from Python — the data-stay-local half of the rule violated by
repetition rather than by transport. `fcs/correlate.
second_order_correlation` is a nested Python loop over the whole trace,
and the file's own docstring records deleting its multi-tau twin for
exactly this reason — the survivor should have followed.

# The job

1. tttrlib: one entry that takes the species filters and emits the full
   auto/cross matrix in a single pass (the correlator already holds the
   stream; the matrix is bookkeeping around it). Photon-native rule
   applies: standard + `*_events` form.
2. chisurf: `species_filtered_correlation` becomes one call; parity A/B
   against the current n(n+1)/2 composition on a real stream.
3. `second_order_correlation`: forward to the `Correlator`; if the
   higher-order (g³) kernel is genuinely missing upstream, add it there
   first (library bugs/gaps go upstream), then forward.

# Definition of done

- [ ] One stream pass for the full fFCS matrix; timing before/after at a
      realistic photon count (the win scales with n — report n=2 and
      n=4).
- [ ] `second_order_correlation`'s Python loop deleted; parity pinned.
- [ ] tttrlib changes committed there with their own tests (examples
      style: linear, matplotlib, no `__main__`).
- [ ] Register rows struck in [PRD-105](prd-105.md).
