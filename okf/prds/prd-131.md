# fit_many everywhere

# Why

Phase-5 row: fit2x ships `fit_many` (GIL-released batch over rows), and
the imaging/MFD paths still call per-row `fit()` from Python loops —
`img_pixel_mle`, `region_mle`, `mfd/fit.py` per-cell/per-span,
`imaging/pixel_maps.py` constructing a `CLSMImage` per window. The
process pool currently papers over the loop cost; batching removes it.

# The job

1. Re-point `img_pixel_mle` and `region_mle` at `fit_many` (they already
   "reach for it" per the survey — finish the reach); results must be
   row-for-row identical to the per-row path, including failed-fit
   sentinel rows.
2. `mfd/fit.py` per-cell loops: batch the cells that share a model; the
   per-span structure decides the batch boundaries.
3. `pixel_maps.py`: hoist the `CLSMImage` construction out of the window
   loop (one image, many windows), then batch the per-window compute.
4. Measure each path before/after at a realistic image size; then decide
   whether the process pool is still worth its complexity on that path —
   deleting it is in scope where the batch alone wins.

# Definition of done

- [ ] No per-row `fit()` loop remains where `fit_many` applies; per-path
      row-identical parity pinned (sentinels included).
- [ ] One `CLSMImage` per image on the pixel-maps path.
- [ ] Timing per path; pool-removal decision recorded per path with its
      number.
- [ ] Phase-5 rows struck in [PRD-105](prd-105.md).
