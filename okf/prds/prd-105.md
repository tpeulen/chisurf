# Why

The owner's rule, stated 2026-09-01 and codified in
[compute-display-line](../architecture/compute-display-line.md):

> Keep it all in bff and tttrlib. Only the things that get displayed move into
> chisurf/Python — so that the data stay local.

Two halves: computation is C++, **and** the data stay where the computation
is. A value crosses the boundary when a human looks at it, and at no other
time. Crossing once per `run()` is fine; once per iteration is the thing the
rule prevents (measured: replacing the optimiser alone bought 1.02x; a C++
loop around a Python callback is a 0.99x *regression* — only removing the
crossing helps). And displaying a value is not licence to recompute it: two
implementations of one algorithm do not average out, they disagree silently.

The rule is already enforced (`test/architecture/test_bff_is_the_backend.py`,
provenance not answers) and scored (`imp.bff/test/minimizer/census_models.py`
for *whether* a model becomes a C++ graph, `bench_models.py` for *how much*
compute is still movable). A first wave landed 2026-09-01/02: one bounded
Levenberg–Marquardt in bff where there were three, the covariance in C++,
`TcspcDecay` and the spectrum chain, the factor graph delegated,
worm-like-chain/Ising/Gaussian-mixture kernels, the Port type system. Every
single move found a latent bug in one of the two implementations it merged —
that is the strongest argument for finishing.

What is missing is not the rule and not the tooling; it is the **plan**: a
sequence, completion criteria, and a register of the duplicates. The census
says 7 of 42 constructible model classes build a graph. The inventory
(2026-09-02, this PRD's survey) says the largest uncrossed boundary is not a
model at all but the **sampler loop**, and that whole subsystems
(`roi/segmentation.py`, `core/ml/`, the burst-analysis numerics) hand-roll
algorithms the engine already ships.

# The method — every move follows this procedure

Learned the hard way across the first wave; not optional.

1. **Measure first.** `bench_models.py` ranks movable compute by
   µs/LM-iteration restricted to the non-native share; `census_models.py`
   answers whether a graph is *the same model* (`MISMATCH` is a defect, not a
   detail). Run them before and after. Mind the two documented biases (linalg
   charged to py; the DEER row's noise).
2. **Parity before forwarding.** Run the chisurf implementation and the engine
   implementation against each other and pin the difference *before* deleting
   either. Every move so far found a bug this way: `FactorGraph::is_complete`
   wrong for exactly the shape every global fit has, `worm_like_chain` with
   `exp(x)` where the paper has `I0(x)`, `rescale_w_bg` being two different
   functions under one name, a third Gaussian kernel hiding behind a flag.
   "Nobody compared them" is what cost a wrong treewidth.
3. **Move the loop, not the kernel.** Granularity sets the runtime: SWIG
   sequence marshalling costs ~50 ns/element, a 512-channel call can be 98%
   wrapper, and a Python loop over a C++ kernel is the worst of both worlds
   (`Gaussians.distribution` crossed 5 times to build one curve). Numpy
   typemaps in, `ARGOUTVIEWM` out, and the iteration structure lives on the
   C++ side.
4. **Delete the Python copy in the same change.** No silent fallbacks — the
   2026-08-31 rule stands: a capability check that only produces a nicer
   message is code, and it gets removed; the library call fails loudly on its
   own. A fallback is legitimate only when it warns, naming the upstream bug
   it works around. Keep a frozen reference copy under the engine's tests when
   the algorithm is subtle (`reference_leastsqbound.py` is the pattern).
5. **Say what the justification is.** Where the movable share is small (the
   distance distributions are 0.2% of movable compute), the justification is
   the placement rule and the single-implementation guarantee, **not speed** —
   write that in the commit body, or a reviewer will expect a speedup and read
   its absence as failure.
6. **Each landing updates the scoreboard**: census/bench re-run, a provenance
   row added to `test_bff_is_the_backend.py` where a new seam exists, the
   board ticket flipped, the touched OKF concept updated.

## Phase 2 — the sampler loop stops crossing

The single largest uncrossed boundary in the tree, untouched by the minimizer
work: `core/fitting/sample.py` (2492 lines) + `ensemble.py` (1215) drive
`for i_step in range(n_steps)` around a Python `_lnprob` →
`model.update_model()` — hundreds of thousands of crossings per MCMC run.
Meanwhile **`imp.bff.Sampler` already exists** as a 1:1 port (stretch, DE with
snooker, blocked Metropolis with dual-averaging warm-up, `lnprob_parts`
semantics, `FactorGraph` blocks).

- [x] DONE 2026-09-02 (`T-20260902-09`; the owner made the contract precise:
      "the boundary only crosses on state updates (progress bar), the
      sampling begin, intermediate saving, and the end").
      `chisurf/core/fitting/sampler_bff.py` routes `walk_mcmc` (metropolis,
      one block, deliberately *without* the curvature seed — a diagonal
      proposal is that sampler's documented contract),
      `walk_mcmc_blocked` (metropolis + the resolved block partition +
      the curvature-covariance seed), `sample_differential_evolution` (de)
      and `sample_ensemble` (stretch) through `bff.Sampler` via
      `graph_objective(allow_priors=True)`. Segmented `run()` delivers the
      contract without a per-step observer: progress, cancellation and a
      partial result dict per segment (one crossing each), continuation
      byte-identical to one long run. Priors ride the port specs; callback
      priors refuse to Python. **Two finds along the way**: the C++ blocked
      proposal drew a fresh normal per matrix *entry* (L·z degenerated to a
      diagonal proposal — invisible until the first non-diagonal factor
      arrived), and the curvature seed itself had never been ported
      (`set_proposal_covariance` + `from_curvature` warm-up protection
      added). Parity is statistical (moments/width), pinned in
      `test/fitting/test_bff_sampler.py`; the Python bodies stay **as the
      refusal path** for graph-less fits — unlike the optimiser there is no
      C++ equivalent for those, so deletion would remove capability, not a
      duplicate. Slice/collapsed/independent-components stay Python by
      design.
- [x] Diagnostics (R-hat, ESS, IAT) stay in Python — they consume finished
      chains, which cross once; unchanged, as intended.
- [ ] `support_plane.py` / `grid_scan.py` / `chi2_scan` re-run whole fits per
      grid point — compliant (once per `run()` each), but verify the
      `_cached_graph` layer holds across the scan so each point is not a
      rebuild (rebuilding was 70% of a covariance call before caching).

# Completion criteria

The PRD is done when all of these hold and are checkable:

1. **Census**: every constructible model class either builds a graph whose
   curve matches its own `update_model()` (no `MISMATCH`), or carries a
   written refusal naming the reason — zero silent fallbacks.
2. **Crossings**: zero Python `update_model()` calls per `fit.run()` for
   graph models (today 2: the final write-back and the display recompute —
   phase 1 removes the second); MCMC chains cross once per run.
3. **Register**: the phase-4 duplication register is empty or every surviving
   row is a documented deliberate exception.
4. **Provenance**: `test_bff_is_the_backend.py` has a row per seam introduced
   above, and fails on a second implementation growing back.
5. **Measurement**: `bench_models.py` re-run and its table recorded in
   `docs/development/benchmarks.md`; the movable (non-native) share is
   reported per model, and no model family is >50% movable without a written
   verdict.

# Decisions needed from the owner

Each moves published numbers, published PRDs, or a large surface; queued,
not taken:

1. **The `i0` transposed digit** — chisurf's Bessel has `3.5156299` where
   Abramowitz & Stegun prints `3.5156229` (reproduced on purpose during the
   WLC port). Correcting it moves every fitted WLC distribution.
2. **`worm_like_chain`'s `distance` flag has never done anything** — delete
   the flag, or implement what it promises.
3. **`datatools.distance_between_gaussian`** shares a name with the bff
   function but computes something different (0.93 apart on the probe) —
   rename flagged as worth doing, left untaken.
4. **PRD-86/PRD-87 direction** — in-tree Python ports (as authored) vs
   forwarding to the tttrlib kernels that now exist. Recommendation: engine
   wins per the placement rule; the PRDs' dependency-removal goal is met
   either way.
5. **MEM engine as the `fcs_maxent` default** — the tttrlib engine route is
   built, pinned and correct but 2–3× slower than the cached-SVD QuickFit
   loop it would replace; single-implementation cleanliness vs measured
   cost. (The loop stays default until taken.)
6. **Gap 3 / literal engine ownership of the data buffers** — measured
   2026-09-02: the duplication costs 0.6 µs per graph build (0.2%), 19.4 µs
   at 65k channels, once per `run()`. The port would invert buffer
   ownership across the app (the 2×N storage, the lock discipline,
   pickling). Recommendation: leave it — this is generic plumbing, not a
   forward model, so refusal-with-a-number applies. Take it only if "the
   data stay local" is wanted *literally* as an architecture statement.
7. **`nusiance.py`'s "full"-mode convolution: rectangular vs. trapezoidal**
   — found 2026-09-02 ([PRD-122](prd-122.md)): the one generic engine
   convolution primitive (`sconv`) computes a trapezoidal-rule integral,
   not the rectangular one `np.convolve` currently computes (verified
   numerically — same shape as the `i0` decision). Four live model families
   depend on the current (rectangular) behaviour; forwarding would silently
   move every fit built on them. Correcting requires either accepting the
   answer shift or adding a rectangular-mode option to `sconv`.

# Non-goals

- **No big-bang move of `core/fluorescence`** (38k lines). PRD-93 stage 4's
  attrition ruling stands; this PRD ranks the attrition so the next touch
  moves the highest-leverage piece.
- **GUI, orchestration, identity and intent stay in chisurf** — the
  compute-display-line's list: what a fit/dataset is, parameter naming and
  vector position, discovery, run policy, everything a view does with a
  number. Diagnostics over finished chains stay Python.
- **No new engine capability for its own sake** — kernels move because a
  chisurf duplicate exists or a model needs a node, not speculatively.
- **MMFDB / server / plugin-hygiene backlog** (`okf/specs/assessment.md`)
  is not claimed here, except BUG-10 which sits on this PRD's path.
