# Where to pick this up

1. **Phase 0, first item: the director-lifetime segfault, board `T-20260901-13`.**
   A Python `Node` held by a `Minimizer` can be garbage-collected while the
   minimizer still holds a `shared_ptr` to it (SWIG director keeps only a weak
   proxy reference), and `T-20260901-10` made `ResidualNode` the fallback for
   *every* model without a graph — so this is a live crash on a path users
   take. The fix is the same `IMP_SWIG_DIRECTOR` treatment
   `MinimizerObserver` already gets (`imp.bff/pyext/swig.i-in` says so in its
   own comment). Reproduce: bind the node to `_` and let the next tuple
   unpacking rebind it; that is how it was found.
2. **Then BUG-10** (`okf/specs/assessment.md`, the only open S1): support-plane
   intervals are wrong on likelihood objectives. It sits in the error-estimate
   path that `T-20260901-10` just moved to C++ — fix it before porting more of
   that path, or the port preserves a wrong answer.
3. Everything else is ordered in **The phases** below. Each phase names the
   board tickets it absorbs; work them through the board, one ticket at a
   time, and flip this PRD's checkboxes as they land.

Traps for whoever picks this up:

- **`bench_models.py` over-reports `py` for linear algebra** (it buckets by
  defining file, so `np.linalg.inv` is charged to Python while the work is
  LAPACK). `DeerTikhonovModel` reads 99% py; much of that is BLAS. Never
  decide a port from that column alone, and never accept a single before/after
  on that model — it is the noisiest row (46–232 ms on an idle machine).
- **The census under-reports refusals**: several families cannot be built from
  a plain `DataCurve` (PDA needs a `pda` attribute, `AVDecayModel` a
  structure), so they show as construction errors, not refusals. A family
  verdict needs a real fixture, not the shared one.
- **The board's build lock and shared-tree hazards apply** to every C++ change
  here — one build directory, one `ninja`, never two `pip install -e .` runs.

# Why

The owner's rule, stated 2026-09-01 and codified in
[compute-display-line](../architecture/compute-display-line.md):

> Keep it all in bff and tttrlib. Only the things that get displayed move into
> chisurf/Python — so that the data stay local.

Two halves: computation is C++, **and** the data stay where the computation
is. A value crosses the boundary when a human looks at it, and at no other
time. Crossing once per `run()` is fine; once per iteration is the thing the
rule prevents (measured: replacing the optimiser alone bought 1.02x; a C++
loop around a Python callback is a 0.99x *regression* — only removing the
crossing helps). And displaying a value is not licence to recompute it: two
implementations of one algorithm do not average out, they disagree silently.

The rule is already enforced (`test/architecture/test_bff_is_the_backend.py`,
provenance not answers) and scored (`imp.bff/test/minimizer/census_models.py`
for *whether* a model becomes a C++ graph, `bench_models.py` for *how much*
compute is still movable). A first wave landed 2026-09-01/02: one bounded
Levenberg–Marquardt in bff where there were three, the covariance in C++,
`TcspcDecay` and the spectrum chain, the factor graph delegated,
worm-like-chain/Ising/Gaussian-mixture kernels, the Port type system. Every
single move found a latent bug in one of the two implementations it merged —
that is the strongest argument for finishing.

What is missing is not the rule and not the tooling; it is the **plan**: a
sequence, completion criteria, and a register of the duplicates. The census
says 7 of 42 constructible model classes build a graph. The inventory
(2026-09-02, this PRD's survey) says the largest uncrossed boundary is not a
model at all but the **sampler loop**, and that whole subsystems
(`roi/segmentation.py`, `core/ml/`, the burst-analysis numerics) hand-roll
algorithms the engine already ships.

# The method — every move follows this procedure

Learned the hard way across the first wave; not optional.

1. **Measure first.** `bench_models.py` ranks movable compute by
   µs/LM-iteration restricted to the non-native share; `census_models.py`
   answers whether a graph is *the same model* (`MISMATCH` is a defect, not a
   detail). Run them before and after. Mind the two documented biases (linalg
   charged to py; the DEER row's noise).
2. **Parity before forwarding.** Run the chisurf implementation and the engine
   implementation against each other and pin the difference *before* deleting
   either. Every move so far found a bug this way: `FactorGraph::is_complete`
   wrong for exactly the shape every global fit has, `worm_like_chain` with
   `exp(x)` where the paper has `I0(x)`, `rescale_w_bg` being two different
   functions under one name, a third Gaussian kernel hiding behind a flag.
   "Nobody compared them" is what cost a wrong treewidth.
3. **Move the loop, not the kernel.** Granularity sets the runtime: SWIG
   sequence marshalling costs ~50 ns/element, a 512-channel call can be 98%
   wrapper, and a Python loop over a C++ kernel is the worst of both worlds
   (`Gaussians.distribution` crossed 5 times to build one curve). Numpy
   typemaps in, `ARGOUTVIEWM` out, and the iteration structure lives on the
   C++ side.
4. **Delete the Python copy in the same change.** No silent fallbacks — the
   2026-08-31 rule stands: a capability check that only produces a nicer
   message is code, and it gets removed; the library call fails loudly on its
   own. A fallback is legitimate only when it warns, naming the upstream bug
   it works around. Keep a frozen reference copy under the engine's tests when
   the algorithm is subtle (`reference_leastsqbound.py` is the pattern).
5. **Say what the justification is.** Where the movable share is small (the
   distance distributions are 0.2% of movable compute), the justification is
   the placement rule and the single-implementation guarantee, **not speed** —
   write that in the commit body, or a reviewer will expect a speedup and read
   its absence as failure.
6. **Each landing updates the scoreboard**: census/bench re-run, a provenance
   row added to `test_bff_is_the_backend.py` where a new seam exists, the
   board ticket flipped, the touched OKF concept updated.

# The phases

## Phase 0 — stabilize the seam (correctness before movement)

The migration's own infrastructure has three known defects; moving more code
onto a seam that crashes or lies is building on sand.

- [ ] **`T-20260901-13`** — `Node` director lifetime: `IMP_SWIG_DIRECTOR` (or
      equivalent ref-keeping) for `Node`, plus a test that drops the Python
      reference mid-fit and survives. *Live segfault on the fallback path
      every non-graph model uses.*
- [ ] **BUG-10** (assessment S1) — support-plane intervals on likelihood
      objectives: F-test threshold wrongly rescaled by χ²ᵣ, adaptive scan
      reporting its own grid edge as a crossing. Fix in the error-estimate
      path *before* further porting there.
- [ ] **`T-20260831-12`** — imp.bff consumes tttrlib's `ExpressionEngine` and
      deletes its own copy ("the ticket that actually satisfies 'not going to
      maintain two split code bases'").
- [ ] **`T-20260831-13`** — tttrlib's ExprTk fallback in `DataStore` silently
      answers multi-argument functions wrong (`hypot`, `atan2`, `clamp`, …).
      Fail loudly or fix; never wrong-and-silent.

## Phase 1 — close the compute/display line's measured gaps

Gap 1 (the numpy Jacobian fallback) closed with `T-20260901-10`. Two remain.

- [ ] **Gap 2 / `T-20260901-11`** — the model curve is read off the graph's
      output port instead of recomputed. Priced at 9–10% of a fit; the
      obstacle named in the concept does not apply (the frozen-value cache is
      about *parameters*; the curve is not a `Parameter`). **`n0` is the
      trap** — publish the curve without it and the displayed amplitude goes
      stale while the curve looks right. Suggested order from the ticket:
      first delete `Fit.run`'s `self.update()` when `minimize` published,
      then attempt the write-back.
- [ ] **Gap 3** — the data are duplicated: `DataCurve` holds `x/y/ey` in
      numpy and `ChiSquared.set_data_arrays` copies them in. End-state:
      `NCurve`/`DataCurve` wrap an engine-owned buffer (zero-copy
      `get_values_ref`/`get_value_view` already exist on `Port`), so "the
      data stay local" becomes literally true. This is a real port with a
      deprecation path, not a rename — the `x`/`y` setters currently rebuild
      a `np.vstack` per assignment, which is a copy per write either way.
- [ ] **Refresh the concept.** `compute-display-line.md`'s measured table and
      gap 1 are stale (pre-`T-20260901-10`); re-measure and rewrite that
      section, and keep the census summary line in it current.

## Phase 2 — the sampler loop stops crossing

The single largest uncrossed boundary in the tree, untouched by the minimizer
work: `core/fitting/sample.py` (2492 lines) + `ensemble.py` (1215) drive
`for i_step in range(n_steps)` around a Python `_lnprob` →
`model.update_model()` — hundreds of thousands of crossings per MCMC run.
Meanwhile **`imp.bff.Sampler` already exists** as a 1:1 port (stretch, DE with
snooker, blocked Metropolis with dual-averaging warm-up, `lnprob_parts`
semantics, `FactorGraph` blocks).

- [ ] Route graph-eligible fits through `bff.Sampler` end to end: parameters
      as ports, objective as the existing graph, chains cross **once per
      run**. The refused-whole rule applies exactly as in `minimize()`: a fit
      that cannot build a graph runs the Python sampler — never a C++ loop
      around a Python callback (measured regression).
- [ ] Diagnostics (R-hat, ESS, IAT) stay in Python — they consume finished
      chains, which cross once; that is the rule's legitimate side.
- [ ] Parity: same seed → same chain against the Python samplers (the engine
      port was written 1:1 for this reason), then the Python
      stretch/DE/blocked-Metropolis bodies become the second implementation
      and are deleted per the method. The slice sampler and anything the
      engine lacks stays, documented as the refusal.
- [ ] `support_plane.py` / `grid_scan.py` / `chi2_scan` re-run whole fits per
      grid point — compliant (once per `run()` each), but verify the
      `_cached_graph` layer holds across the scan so each point is not a
      rebuild (rebuilding was 70% of a covariance call before caching).

## Phase 3 — every model family on the graph, or a written refusal

7 of 42 constructible model classes build a graph today. The goal is not 42 —
it is that every family has either a graph **or a written verdict** ("what is
the curve, and whose is it") in `okf/`, so the next reader knows the state.

- [ ] **TCSPC eligibility widened**: pile-up (Coates) and the DNL
      linearisation table move into `TcspcDecay` (~200 lines in
      `tcspc/corrections.py`; two of the seven explicit refusals in
      `_lifetime_objective`).
- [ ] **`T-20260901-08`** — the distance distributions with no node. Kernels
      already ported (2026-09-02); what is left is node wiring
      (`PolymerDistances` with a mode; `IsingChainModel` its own node). *For
      the graph, not for speed — 0.2% of movable compute; say so.*
- [ ] **FCS gets a graph** — the whole family sits on `ResidualNode`.
      `fcs/enderlein.py` (the `MdfFCSModel` half of **`T-20260901-15`**:
      110 ms/curve, 93% Python, a nested closed-form loop — "the same shape
      as the Ising port") and `fcs/saturation.py` (1099 lines, full numerical
      FCS forward model with its own cache as the tell) become engine
      kernels behind an FCS curve node family; every FCS model leaves
      `ResidualNode` in one step.
- [ ] **DEER: arithmetic before port** (the other half of `T-20260901-15`) —
      `_gcv_score` recomputes the α-independent `A.T@A` / `L.T@L` inside the
      24-α loop and forms a full `A@inv@A.T` for a trace. Fix in Python,
      measure, and only then decide whether a port is worth it.
- [ ] **`T-20260901-09`** — written verdicts for DEER, ICS, PCH/FIDA,
      PDA2c/3c, MFD, stopped-flow: what is the curve, whose is it
      (tttrlib already owns `Pda`, `Pda3cCore`, `PdaBurstLikelihood`,
      `PhotonCountingHistogram`), and whether a node is warranted. Real
      fixtures per family (the census construction-error trap).
- [ ] **Nested optimisers deleted**: `DeerGaussianModel`/`DeerRiceModel` and
      `pch/fida.py` each run their own `scipy.optimize.least_squares`
      *inside* `update_model` — an optimiser inside the outer optimiser's
      residual, and implementations three and four of bounded LM. Onto
      `bff.Minimizer` or refused with a reason.

## Phase 5 — batch the chatty photon/burst paths

The data-stay-local half of the rule, applied to per-burst and per-photon
loops that issue one C++ call per item.

- [ ] Per-burst `TTTR` slicing loops (`burst/bva.py`, `burst/photons.py`,
      `fio/fluorescence/burst.py` constructing a `TTTR` per file inside the
      loop) → one batched C++ call over the burst table, which already lives
      in a C++ `DataStore`.
- [ ] fFCS: `species_filtered_correlation` issues n(n+1)/2 separate
      `Correlator` passes over the same photon stream from Python → one call
      that emits the full species auto/cross matrix.
- [ ] `GopichSzabo`: the engine object is rebuilt on **every likelihood
      evaluation** inside a scipy loop, with a redundant numpy
      eigendecomposition as a guard — persist the engine, drop the guard,
      move `fit()` onto `bff.Minimizer`.
- [ ] HMM: forward/backward/Viterbi are already tttrlib; the EM loop and
      M-step around them are Python (`for _ in range(n_iter)`). Pair with
      [PRD-77](prd-77.md)/tttrlib PRD-013 — the whole EM iteration engine-side.
- [ ] fit2x: `fit_many` (GIL-released batch) everywhere the per-row `fit()`
      is currently used (`img_pixel_mle`, `region_mle` reach for it).
- [ ] MFD per-cell/per-span loops (`mfd/fit.py`, `prepare.py`) and imaging
      `pixel_maps.py` per-window `CLSMImage` constructions (the process pool
      is the mitigation; batching is the fix).

## Phase 6 — the car gets clean (package shape)

intent: data model, fit lifecycle, discovery, run policy, views.

- [ ] `core/math` shrinks to forwarders + orchestration: `rdf.py`,
      `distributions.py`, `special.py`, the `datatools`/`signal` scalar loops

- [ ] **Direction decision for `roi/segmentation.py` (1454 lines) and
      `core/ml/` (~2650 lines)** — both are from-scratch reimplementations

      `core_distances`/`mutual_reachability_mst`. Under the placement rule
      the engine wins (recommendation: forward, delete, re-point 86/87);
      decision 4 below.
- [ ] **`T-20260901-05` remnants**: `core/graph/` (1966 lines of
      general-purpose graph library — the layout half is a genuine open
      question), `fitting/graphview.py` (880 lines of layout), the `.csp`
      wrapper in `core/project/` (sessions already load through
      `bff.Session`).
- [ ] Structure/geometry (`structure/protein.py` O(N²) scalar loops,
      `structure/cluster.py`): `chisurf.Structure` is closed to new code

- [ ] Chisurf-side governance: a `fitting`-subsystem concept refresh
      (`okf/subsystems/fitting.md` predates the whole migration) and a
      subsystem concept for the graph-objective seam
      (`core/fitting/minimizer.py`), which is the busiest seam in the tree
      and currently documented only at architecture level and in imp.bff's
      log.

# Completion criteria

The PRD is done when all of these hold and are checkable:

1. **Census**: every constructible model class either builds a graph whose
   curve matches its own `update_model()` (no `MISMATCH`), or carries a
   written refusal naming the reason — zero silent fallbacks.
2. **Crossings**: zero Python `update_model()` calls per `fit.run()` for
   graph models (today 2: the final write-back and the display recompute —
   phase 1 removes the second); MCMC chains cross once per run.
3. **Register**: the phase-4 duplication register is empty or every surviving
   row is a documented deliberate exception.
4. **Provenance**: `test_bff_is_the_backend.py` has a row per seam introduced
   above, and fails on a second implementation growing back.
5. **Measurement**: `bench_models.py` re-run and its table recorded in
   `docs/development/benchmarks.md`; the movable (non-native) share is
   reported per model, and no model family is >50% movable without a written
   verdict.

# Decisions needed from the owner

All four move published numbers or published PRDs; queued, not taken:

1. **The `i0` transposed digit** — chisurf's Bessel has `3.5156299` where
   Abramowitz & Stegun prints `3.5156229` (reproduced on purpose during the
   WLC port). Correcting it moves every fitted WLC distribution.
2. **`worm_like_chain`'s `distance` flag has never done anything** — delete
   the flag, or implement what it promises.
3. **`datatools.distance_between_gaussian`** shares a name with the bff
   function but computes something different (0.93 apart on the probe) —
   rename flagged as worth doing, left untaken.
4. **PRD-86/PRD-87 direction** — in-tree Python ports (as authored) vs
   forwarding to the tttrlib kernels that now exist. Recommendation: engine
   wins per the placement rule; the PRDs' dependency-removal goal is met
   either way.

# Non-goals

- **No big-bang move of `core/fluorescence`** (38k lines). PRD-93 stage 4's
  attrition ruling stands; this PRD ranks the attrition so the next touch
  moves the highest-leverage piece.
- **GUI, orchestration, identity and intent stay in chisurf** — the
  compute-display-line's list: what a fit/dataset is, parameter naming and
  vector position, discovery, run policy, everything a view does with a
  number. Diagnostics over finished chains stay Python.
- **No new engine capability for its own sake** — kernels move because a
  chisurf duplicate exists or a model needs a node, not speculatively.
- **MMFDB / server / plugin-hygiene backlog** (`okf/specs/assessment.md`)
  is not claimed here, except BUG-10 which sits on this PRD's path.
