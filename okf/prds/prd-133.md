# Why

Phase-4's last register row. A fallback inside a `try/except` is the
documented danger shape: when the import or the kernel breaks, the
program does not crash — it silently degrades onto the twin, and the twin
has not been under test. Six such twins are kept "by design" (BOCPD,
recurrence, Gopich–Szabo, PCH/FIDA, blind IRF, MaxEnt). "By design"
needs to mean *decided per case*, not *left over*.

# The job

Per fallback, in order:

1. Establish reachability: under what condition does the Python twin run?
   If the answer is "an engine older than the tree requires" — the tree
   pins its engines; the twin is dead code. Delete it and let the import
   fail loud.
2. If genuinely reachable (an optional engine feature, a platform hole):
   the fallback stays but must **warn, naming the gap it covers** (the
   library-bugs-upstream rule's fallback contract) and carry a test that
   exercises the fallback path itself — an untested fallback is worse
   than none.
3. Either way, record the decision in the register row: dead-deleted or
   live-guarded, per name.
