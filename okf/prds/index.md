# PRDs — Design Notes

Product-requirement / design notes driving current work. Each PRD is one **self-contained** concept (`prd-<n>.md`) carrying its full design text and keeping its **persistent number** as a stable id; references to external software are described by role, not named. These were formerly the top-level `overhaul/` folder, now retired into this group. The authoritative implementation ordering is [PRD Implementation Order](master-order.md).

* ✅ [PRD-80: Retire mdtraj — DCD frames, RMF3 hierarchies](prd-80.md) — `mdtraj` is the only reason `pytables` and, through it, `numexpr` are installed. IMP already covers the structure side (34 import sites) but has **no DCD reader at all** — verified in its source, where the only `dcd` matches are prose about citing a file in a deposition — so a DCD codec is the one genuinely new piece of code. Scope is narrower than it looks: mdtraj's HDF5 trajectory format lives in exactly **one** file, and the 24 other `.h5` users (TTTR photons, bursts, MMFDB) are untouched. MDAnalysis was measured and rejected at 142 packages against mdtraj's 70, and it reintroduces `networkx` and `tqdm`. Storing trajectories *as* RMF3 was tested and rejected too: **10.5 s to read 200 frames of 2500 atoms against 14 ms for DCD** — RMF's per-node key model is the wrong shape for dense coordinates, so DCD holds frames and RMF3 holds hierarchies.
* ✅ [PRD-81: chinsole — one console seam, and the end of qtconsole](prd-81.md) — ChiSurf ran an in-process Jupyter kernel to provide a text box that runs Python, and had **three** hand-rolled consoles besides. chinsole is the in-tree replacement: a Qt-free interpreter (`chisurf/core/console/`) under a Qt widget (`chisurf/gui/chinsole/`), so the whole of execution is testable without a `QApplication` — which the kernel design never was. `qtconsole` is retired and banned by the guardrail. Measured: dropping it alone is **264 → 262** packages, because `notebook<7` drags `ipython` back in regardless; the remaining **83** need the external notebook server to go, which is a user-visible feature removal and out of scope here.
* ✅ [PRD-82: The table layer onto the DataStore — pandas out of the tree entirely](prd-82.md) — `chitable`'s adapter architecture, the burst tables, the HDF5 writers and the CSV readers all moved onto the simulation library's columnar store, and pandas was then eliminated from `chisurf/` completely (scope changed mid-PRD on explicit direction: "no pandas AT ALL"), not merely from the storage path. Half the memory on a burst table (109.5 → 60.2 MB), types and missing values that survive a file, `pytables` genuinely gone from a freshly solved environment, and `pandas` itself struck from `pixi.toml`/`pyproject.toml`/`rattler-recipe/recipe.yaml` — closure measured 256 → 255 with `conda create --dry-run`. It stays declared only in `pixi.toml [feature.test.dependencies]`, for tests that use it as an independent oracle or to simulate a file an external tool wrote. Open, unrelated to the pandas work: acceptance criterion 3 (a file written by a previous release still needs the optional HDF5 package to open) and criterion 6 (the memory saving is unmeasured past 113 rows).
* 🚧 [PRD-83: Retire pyqtgraph — the umbrella, and the 3-D half nobody owned](prd-83.md) — `pyqtgraph` is reached from 14 files, one `.native` escape hatch, and **three subsystems that are not plotting at all**: OpenGL views, a parameter tree and a dock area. PRD-64 owns the 2-D seam; this owns the end state — *is pyqtgraph still installed, and what is the last thing keeping it here?* The **3-D half is closed**: ChiMOL renders through PyOpenGL on a plain `QOpenGLWidget`, and its last pyqtgraph import was a 13-line module computing a flag **nothing imported**. The shim it left behind was not merely unnecessary but actively harmful — `opts["center"]` was a second store maintained from seven call sites and read by nobody, and the picking helper it existed for read that `QVector3D` straight into `numpy`, so every click in the viewport raised.
* 📋 [PRD-84: Units all the way out — parameters, axes and files that say what they mean](prd-84.md) — A number in ChiSurf is a bare float, and what it is measured in lives in a column name when somebody remembered, in an axis label when somebody typed one, or nowhere. **Four** in-band conventions encode it and disagree: `"Duration (ms)"` suffixes, `"Tau | ns"` headers, and two bare factor tables in the DEER and FCS readers. `FittingParameter` has no unit at all, so a fitted lifetime leaves the program as a bare number. The vocabulary half has landed — `_mmfdb_units` declares 28 codes with symbols and SI factors, 15 of them mmCIF's own, and a `.pto` column now carries its unit — and the rest of the stack is open under one rule: **unitless inside, units at every boundary a person or a file sees**. Explicitly *not* a unit-aware numeric type: arrays stay numpy arrays and the fitting engine stays unitless, because dimensional analysis in a Jacobian is a way to make a fit slower and wrong.
* 🚧 [PRD-85: Drop guards — an opt-in nag-before-commit pattern for file drops, first applied to .pto conversion](prd-85.md) — **Part A done**: `chisurf/gui/widgets/dropguard.py` adds a small registry (`register_drop_guard`/`apply_drop_guards`, mirroring the existing AutoForm section registry) that a drop zone opts into **by name**, so different drop zones can nag about different things — or nothing — rather than one blanket behaviour. The one concrete guard shipped, `tttr_to_pto`, closes a real gap: the Qt-free conversion path (`pto.Measurement.create`) was correct, non-destructive and completely unwired — a dropped `.ptu` was read where it lay, forever. Wired opt-in at the drop zones that genuinely load a measurement, it offers convert-now (original kept or deleted, only after checksum verification) or use-as-dropped, once, dismissably, safe-by-default headless; plus a separate zero-setting drop-only tool that works **both ways** — pack a vendor file into `.pto`, or unpack a `.pto` back to the vendor file(s) it embeds. **Part B in progress**: `chisurf.core.fio.decimate.thin_for_plot` (min/max-per-bin, keeps bursts/dips a plain stride would alias away) is wired into `burst_selection`'s raw per-photon diagnostic plots, budget `data_loading.max_plot_points` (default 1.5M) — found necessary the moment a merged multi-file `.pto` made a real diagnostic plot draw millions of points and lag. Not yet in `chiplot` itself or the other seven plugins Scope B named.
* 📋 [PRD-86: An in-tree segmentation core — Otsu, border-clearing, peak-finding, watershed — closing scikit-image out of ChiSurf's imaging path](prd-86.md) — `chisurf.core.roi.props` already reimplements `skimage.measure.regionprops` property-for-property, so "what is this region" is dependency-free; "which pixels are a region" is not. Molecule MLE's actual segmentation (`segment_molecules`) imports `skimage.filters`/`feature.peak_local_max`/`segmentation.{clear_border,watershed}` **unconditionally, with no fallback** — the plugin cannot segment a molecule without scikit-image; colocalization's `_watershed_split` uses the same pair but already degrades gracefully (`try/except ImportError` → plain connected components), the target shape both should converge on. Of the four calls, Gaussian smoothing needs no port at all (`scipy.ndimage.gaussian_filter` already does it); Otsu and border-clearing are small, well-known algorithms; local-maxima and marker-controlled watershed are the real centrepiece — a genuine classical algorithm, closer in effort to the in-tree `marching_cubes.py` port than to the `pdb2pqr` single-atom fix it otherwise resembles in spirit. Proposed home: `chisurf/core/roi/segmentation.py`, tested the same way `regionprops` already is (`pytest.importorskip("skimage...")`-guarded parity tests) — and, unrelated to the port itself, the CLSM plugin's `skimage.io.imsave` (an aliased-import guard-bypass of the retired `imageio` dependency) was found and fixed directly during scoping.
* 📋 [PRD-87: chisurf.core.ml — the four estimators the tree actually uses, and the end of scikit-learn](prd-87.md) — `scikit-learn` (with `joblib`, `threadpoolctl`, `narwhals` and `hdbscan`, **256 → 251** packages / 46 MB) is installed so that **five files** can call **four estimators**, and the used surface is exhaustively `GaussianMixture`, `MLPRegressor`, `StandardScaler`, `KMeans`, `PCA`/`IncrementalPCA` — no pipelines, no model selection, no metrics. The tree meanwhile *already contains* most of them, sealed as private helpers inside `chisurf/core/math/hmm.py`: the Cholesky log-density for all four covariance layouts, and a complete k-means++ with `n_init` restarts. Counting the companion exploration tool's `GaussianMixtureFixedEM` — written because the library **cannot fix a subset of means or covariances** — there are **four implementations of two algorithms**, none sharing a line, with the dependency still installed. The port mirrors the library's own package layout and public attribute spellings so each call site changes by one import, and makes the fixed-parameter masks a first-class option rather than a fork. **The dependency does not leave when chisurf stops importing it**: `hdbscan` requires `scikit-learn`, and the fallback path reaches for `sklearn.cluster.HDBSCAN` when the standalone package is absent — a knot that cannot be cut from either end, so HDBSCAN (mutual-reachability MST + condensed tree + excess-of-mass) is the one genuinely new algorithm and the honest place this may stop.
* 📋 [PRD-88: Every provenance graph reconstructs — the source/sink matrix, and the chains between them](prd-88.md) — A container's provenance is only worth having if **every** artifact in it reaches the primary data, and that is a property of the whole graph written by ~20 independent writers against a dozen kinds of source. It was being tested on **one synthetic two-step chain**. A throwaway audit driving the real writers against real files — ~200 lines, an hour — found **6 of 26 artifacts with a broken or incomplete lineage**, four of them one root cause: `instrument_uid` was recovered on reopen by matching a single artifact kind, so a container whose source is *not* photons (ebFRET starts from binned traces, and `create` takes an `artifact_kind` precisely so a `.dat` is not called a photon stream) came back with no primary — and a writer passing `derived_from=()` then recorded **no parent at all**. Invisible because a writer that *creates* the container in the same call never asks again: it only shows on **reopen**, which is what a second analysis on the same measurement does and what no test did. This defines the matrix (11 source kinds including the sidecar-carrying SPC, the generated sources, and the no-primary case; ~20 writers with their artifact counts and grains) and the **nested chains** that have no coverage at all — 5-deep fan-in through burst fusion, a raster in the middle of an imaging chain, calibration as a second relation type, and the reopen path where the found defect lived.
* ✏️ [PRD-92: Spot finding is not lifetime fitting — a region-property MLE fed by a spot finder that persists its regions](prd-92.md) — `sm_image_mle` segments, measures, gathers photons and fits inside one 897-line core, and **`fit_molecules` re-runs `segment_molecules` itself** — so `segmentation_preview()` returns exactly the labels the fit will use and the fit ignores them, re-deriving a second segmentation that agrees only for as long as every setting reaches both paths. The regions are never persisted, so a segmentation cannot be reviewed, corrected, compared or shared, and none of the spot detection the tree has grown since (`blob_log`/`blob_dog` with their scale space, `difference_of_gaussians`, `white_tophat`, `img_tracking`'s à-trous product) can feed the fit. Split into a `spot_finder` plugin that detects and **writes its regions into the `.pto`**, and a renamed `region_mle` that fits the regions it is handed — "molecule-wise" names the sample, not the operation. The one decision that cannot be deferred: a table of `regionprops` scalars **cannot say which photons belong to a region** (the fit reaches them by `prop.coords` → `tttr_indices`), so the persisted artifact is a **pair** — an `image_data` label raster keyed by a `label` column — and the table copies the burst-companion merge-by-position rule (one row per region *including* the ones the fit skipped, sentinel never absent). Both halves are **batch** tools and the batch half is not a for-loop: there are two batch implementations today — `api/molecule_mle.py::analyze_request` (CLI + RPC, writes the container) and `gui/view_model.py::run()` (GUI, writes a TSV and **no container at all**) — every failure mode is a `continue` that silently shortens the joint table, the joint file lands next to `files[0]`, measurements are keyed by a string path, and the IRF and G-factor are rebuilt from the same measurement once per file. One Qt-free runner replaces both, returning a **run table with one row per input whatever happened to it** (`ok`/`empty`/`failed`/`skipped`) — the sentinel-row rule one level up — with results in each measurement's own container, a cross-measurement table as a derived view rather than a format, IRF preparation once per batch, and cancel. Adds a 3-deep photons → regions → fits chain to [PRD-88](prd-88.md)'s matrix; the estimator half (`Fit2x`/`fit_many`/VV-VH/IRF prep) is deliberately untouched, and the acceptance test is that the split reproduces today's per-region parameters to the last significant figure.
