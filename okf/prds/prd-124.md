# One regularised inversion

# Why

Five in-tree solvers of the same problem class (non-negative regularised
linear inversion: Tikhonov, MaxEnt, GCV/L-curve selection) and an engine
that ships the pieces (`tttrlib` `Nnls`, `MaxEntQp` — header-only since
2026-09-02 — and `Mat`). Two implementations of one algorithm do not
average out; five certainly do not.

# The job

1. Inventory the five call surfaces and their objective conventions first
   — `fcs/maxent.py` renormalises weights to mean σ≈1 (QuickFit), the
   engine takes ν=√(2α); a port that ignores a convention fits a
   different objective (this bit once already — see
   `test/models/test_fcs_maxent_engine.py`'s docstring).
2. One chisurf-side seam module (`core/fitting/inversion.py` or similar)
   that maps every caller's convention onto the engine, with the
   convention translation *tested per caller*.
3. **Respect PRD-105 owner decision 5**: the `fcs_maxent` default stays
   the cached-SVD loop until the owner takes the 2–3× cost. The seam can
   land with the loop as one of its backends — the point is one *surface*,
   the backend count follows the decision.
4. GCV/L-curve selection loops: hoist the α-independent factorisations
   (the DEER 3.6× hoist is the template) before considering any port.

# Definition of done

- [ ] Every regularised-inversion caller goes through the one seam;
      per-caller convention tests pin the objective.
- [ ] Duplicated solver bodies deleted (or reduced to the one
      loop-backend decision 5 keeps alive).
- [ ] Before/after timing per caller; no regression lands without the
      owner accepting it.
- [ ] Register row struck in [PRD-105](prd-105.md).
