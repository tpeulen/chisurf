# core/math forwarder slice

# Why

PRD-105 phase 4: one implementation per algorithm. These rows have a
shipped engine owner and no design question — each is a
measure-A/B-then-forward job, the same shape as the pile-up port.

# The job

Per row: parity A/B at current behaviour first (every previous move found
a latent bug in one of the two copies), then forward, then delete.

1. **Richardson–Lucy** — `math/linalg` + `math/optimization` (one wraps
   the other) → `tttrlib.richardson_lucy_2d`, which
   `imaging/restoration.py` already uses. Two callers to re-point.
2. **Polymer distributions** — `math/functions/rdf.py` Gaussian chain,
   SAW-ν, WLC → `imp.bff` `PolymerChain.h` kernels (`ising_chain` already
   forwards; these follow the same shape).
3. **Decay-convolution straggler** — `models/tcspc/nusiance.py:945`'s
   `np.convolve` branch beside the tttrlib branch → `tttrlib.fconv*`,
   branch deleted.

Staged behind owner decisions (do **not** forward until taken — the
engine values differ on purpose):

- **Bessel `i0`** (`math/functions/special.py`) — the transposed digit,
  PRD-105 decision 1. Forwarding changes every fitted WLC distribution.
- **`distance_between_gaussian`** — same name, different function than
  bff's (0.93 apart on the probe), PRD-105 decision 3.

# Definition of done

- [ ] Rows 1–3: engine is the single implementation, in-tree copies
      deleted, parity pinned in a test each, before/after timing reported.
- [ ] The phase-4 register rows struck in [PRD-105](prd-105.md).
- [ ] The two blocked rows carry a pointer to their decision — visible in
      this PRD and the register, not silently skipped.
