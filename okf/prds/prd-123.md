# Burst kernels onto tttrlib

# Where to pick this up (2026-09-03, after review)

What actually landed (`7b2175a2b`/`031f5dec8`): the Kalman forwarder, BVA
via `tttrlib.BVA` (old `compute_bva` deleted), BVA per-measurement
batching, and a real sentinel-row bugfix in `read_burst_analysis` (the
review pass then fixed the regression that bugfix's default-format change
exposed: `analyze_file(output_dir=...)` wrote nothing under the `["pto"]`
default — the request-implies-format rule now applies to the direct path
too, `test/fluorescence/test_mfd_burst_roundtrip.py` green again). Still
open, in order:

1. ~~`math/signal.find_bursts`~~ — DONE 2026-09-03 (owner ruling "the
   burst stuff belongs to tttrlib"): now
   `tttrlib.BurstFilter.bursts_from_mask`, bit-faithful to the NumPy
   reference including its documented gap off-by-one (max_gap=g bridges
   g+1), A/B pinned in tttrlib
   `test/python/burstfilter/test_bursts_from_mask.py` (22 tests) against
   the transcribed reference; chisurf's `find_bursts` forwards.
2. **2CDE was never touched** — nothing in chisurf references
   `tttrlib.TwoCDE`.
3. **The Kalman "parity" test pins nothing against a reference** — the A/B
   half died with the Python twin (PRD-133); it needs a frozen-reference
   transcription or golden numbers on a deterministic fixture.
4. The per-burst slicing loop in `burst/photons.py` is unbatched —
   re-verified 2026-09-03: it crosses C++ once per *file* (arrays pulled
   into numpy caches once), so this is a Python-iteration batching win,
   not a live per-item crossing; the batched form is a tttrlib kernel
   taking the burst table and emitting concatenated arrays + offsets.
5. No timing was recorded for any of it.


# Why

Two PRD-105 rows that belong together: phase 4's duplicate burst kernels
(`burst/bocpd.py`, `cusum.py`, `count_rate.py`, `kalman.py`,
`math/signal.find_bursts` vs tttrlib `BurstSearchDispatch` +
`BurstFilter`; `burst/bva.py` vs `tttrlib.BVA`/`TwoCDE`) and phase 5's
chatty loops (`burst/bva.py`, `burst/photons.py`,
`fio/fluorescence/burst.py` constructing a `TTTR` object *per burst or
per file inside the loop*). Forwarding the kernel without batching the
loop keeps the crossing; batching without forwarding keeps the duplicate.

# The job

1. Parity A/B per kernel at current behaviour (BOCPD, CUSUM, Kalman,
   find_bursts, BVA, 2CDE) against the tttrlib twins — on the same real
   file, not synthetic-only; the burst seam is where misalignment is
   silent (see [burst-companions](../subsystems/burst-companions.md)).
2. Forward, delete the Python bodies, keep chisurf's parameter surface.
3. Replace the per-burst slicing loops with one batched call over the
   burst table (already in a C++ `DataStore`) — the engine side may need
   a `*_events`-form entry per the photon-native rule; file/land in
   tttrlib where missing.
4. Timing before/after per path; the loops are the measured cost, report
   them separately from the kernels.

# Definition of done

- [ ] No burst search/change-point/BVA/2CDE arithmetic left in chisurf;
      parity tests pin each forwarder.
- [ ] Zero per-burst `TTTR` constructions inside loops on the ported
      paths.
- [ ] Companion-file outputs byte-identical on the reference measurement
      (the column-wise merge contract makes silent misalignment the
      failure mode — test it, not just the values).
- [ ] Register rows struck in [PRD-105](prd-105.md); board ticket per
      landing.

# Traps

- One row per burst *including skipped bursts* — a batched kernel that
  drops failed bursts corrupts every companion downstream.
- The Python fallbacks "kept by design" for BOCPD are phase 4's audit row
  ([PRD-133](prd-133.md)) — do not delete them here without the audit.
