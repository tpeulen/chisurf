## Context

ChiSurf (branch `mcts-native-baseline`) must reach a release-ready state. The owner
develops the **entire stack** — chisurf, emtk, chimol, **ndxplorer** (`modules/ndxplorer`,
its own repo on branch `development`), tttrlib, imp.bff, mmfdb — so every defect is fixed
in the repo that owns it, fundamentally, with tests, and never patched around in chisurf
or in a plugin. No repo in this list is "upstream" or "someone else's": an agent that
finds the root cause in ndxplorer or emtk fixes it there and commits there. Clean code wins over working-but-ugly;
legacy/compat code is removed, not maintained; the target is "modern everywhere".

What release-ready means here (the owner's list, grouped):
1. **Data model:** `.pto` is the prime format at every burst step (selection, sub-ensemble
   histograms, FCS, burst-wise FCS, H2MM segmentation, MLE), repeated runs with different
   parameters coexist in one `.pto`, a run picker/browser lets the user jump between
   steps, a legacy export keeps Margarita/Seidel tools working. The project `.cs.pto`
   autosaves without asking and carries sampling chains as DataStores; ndX opens
   `.cs.pto`.
2. **UI:** every plugin is emtk + AutoForm with `?` help, a Guide tour with a shippable
   demo, tooltips on every active widget, all strings through i18n, sensible initial
   sizes with remembered geometry/docks; hubs show setup once as step 0; `Imaging`
   folds into `Spectroscopy`; emtk itself gets keyboard navigation, working zoom-out in
   the node graph, proper window frames, grid/stretch layouts, a usable 3-D PSF view,
   and games whose keys land. If emtk is proven as good or better than Qt, **Qt is
   removed**. pyqtgraph goes if chiplot covers it.
3. **Quality:** an e2e test clicks every plugin; CI runs it; no `.ui` files, no build
   artifacts, no stray folders in `~/dev`; every open issue in the OKF bundle is resolved
   and the bundle is lint-clean; docs show each workflow with real screenshots.
4. **Science/infra:** MCTS policy retrained + a fit-settings search; UI snappy; imp.bff
   modular like tttrlib; mmfdb aligned with flrCIF and the public-databank picture.

The implementation will be done by **less capable agents working in parallel**. This plan
is therefore written as self-contained workstreams with exact anchors, ordered steps,
tests, acceptance commands and traps. An implementing agent should never need to
re-derive a finding from this document; if it must, that is a defect in this plan — fix
the plan (in `okf/`), then continue.
