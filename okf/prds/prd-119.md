# FCS kinetics "full" mode as a node over the FcsSaturation kernel

# Why

The saturation compute moved to `IMP.bff` `FcsSaturation` on the owner's
placement ruling (2026-09-02, parity 5e-14). `FCSKineticsModel`'s `"full"`
mode still evaluates it from Python inside `update_model`, so a kinetics
fit crosses per iteration. The family verdict records the node as the
deliberate remainder.

# The job

1. Add a node wrapping `fcs_saturated_curve_shape`: ports for power,
   extinction, brightness, w0, z0, diffusion; the rate-scheme matrices set
   once as configuration when their entries are fixed, refused when a rate
   is free (a matrix port is real work — do not build it speculatively).
2. Wire `FCSKineticsModel` (`"full"` mode) to it through the same
   producer-node pattern as [PRD-118](prd-118.md) — land 118 first and
   reuse its builder hook.
3. Closed-form kinetics modes: check whether they are expressible strings
   (the `GeneralFCSModel` pattern) and take the cheaper route where they
   are.

# Definition of done

- [ ] Node curve == `update_model` at 1e-10 in `"full"` mode.
- [ ] A free rate-matrix entry refuses the graph (unclaimable), not
      silently freezes.
- [ ] Census: `FCSKineticsModel` flips to yes (its `update_model` no-op
      without a payload — see [PRD-121](prd-121.md) — must not fake the
      parity).
- [ ] Before/after fit timing reported; the kernel is ~1.0 ms/evaluation,
      so the win to claim is crossings, not arithmetic.

# Traps

- `K[target, source]` convention everywhere except 2D-FLC — the fixture
  trap that bit the saturation port (an all-zero curve agrees vacuously;
  assert the curve is non-degenerate first).
- The kernel's Hankel matrix is cached on its grids; keep the node's
  evaluation from rebuilding it (same trap as PRD-118).
