# Summary

ChiSurf's long-term direction is to remove Qt and draw every tool with emtk. About 20
plugins still open a Qt window, or an emtk window that only works inside a Qt tool
class. This PRD tells an implementing agent **exactly how to port one plugin**, in
what order to port them, what proof to leave behind, and when to stop and ask. A
reviewer (the owner's main agent) will check each port **only from the evidence files
and the report**, so anything not measured and written down counts as not done.

Read this whole document before touching a file. It is long on purpose. Do not
improvise where it gives an instruction; where it does not, stop and ask (section "When to stop and ask").

# Non-goals — do not do these

* Do **not** redesign a plugin, rename its settings, or "improve" its science. A port
  moves the same controls and the same behaviour onto emtk.
* Do **not** delete or edit the legacy Qt files (`gui/tool.py` etc.). They are the
  baseline and the fallback; a separate change deletes them after review.
* Do **not** build a new widget, base class, scaffold or framework. If emtk lacks
  something a port needs, **stop and report it** (section "When to stop and ask"); the reviewer adds it to
  emtk.
* Do **not** touch plugins that are not in your assignment, emtk itself, or
  `okf/plugins/emtk-migration-inventory.md`'s other sections.
* Do **not** port anything in the "Excluded" list (section "Backlog, waves, and the pilot gate").

# Hard rules (each one is checked)

1. **Shared working tree.** Other agents and the owner have uncommitted edits in this
   repository. Never run `git reset --hard`, `git checkout -- <path>`, `git restore`,
   `git clean`, `git stash`, `git add -A`, `git commit -a`, or any `--force`. Never
   commit a file you did not write. Before you commit, run `git status --short` and
   `git diff --stat -- <your paths>`; if a file you must edit already shows changes you
   did not make, **stop and ask**.
2. **Commits.** Local commits only, never push. The message is plain text (subject +
   body), authored as the configured user. **No trailer of any kind** — no
   `Co-Authored-By`, no "Generated with".
3. **Agent board.** Before starting, read `okf/agent-board.md` and append a claim (your
   plugin id, the files you will touch). Update it when done or blocked.
4. **New GUI = spec + emtk, never Qt.** The form is declared in a `*.view.json` and
   drawn by `emtk.view_form.draw_form`. Hand-written `im.*` code is allowed only for
   what a spec cannot express: plots, images, canvases, and the toolbar/status strip.
   **Never hand-draw a table** (use the spec's `table` / `data_table` section) and
   **never import Qt** in the port (`qtpy`, `PyQt5`, `PySide*`, `chisurf.gui.*`).
5. **Emtk default look.** Use emtk's default style. No `WINDOW_BG`/`PANEL_BG`
   palettes, no custom fonts. The only colours you may set are ones that carry data
   (a gate colour, a colormap). Run/Stop buttons are plain buttons.
6. **No emoji in labels.** Write `Open`, not `📂 Open`.
7. **Every control has a tooltip** (`description` in the spec, or
   `im.set_item_tooltip` right after a hand-drawn control). The tool measures this;
   the list of untooltipped controls must be empty.
8a. **No invented data.** A port draws only what the model computed or loaded. An empty state is a message
   ("Load a file"), never a plausible-looking curve. A demo is allowed only behind an explicit action labelled
   Demo whose data the plugin generates itself (as `img_flow` does); two ported burst apps drew synthetic
   decays and a seeded random scatter as if they were results (see known issues), which is a correctness
   defect, not a placeholder.
8. **Numbers come from the tool, not from you.** Every count, size and pass/fail in
   your report is pasted from a command's output (section "Evidence and report"). Never estimate.
9. **Test what you touch.** Every plugin you change ends with its whole test folder
   green, plus the new tests in section "Tests to write". If a test that was already red is unrelated
   to your work, do not fix it and do not hide it: write it in the report under
   "Pre-existing failures" with the command and output.
10. **Never name a PRD in source code** (this file's number must not appear in `chisurf/`).
    Point at OKF concepts instead.

# What "ported" means (Definition of Done)

A plugin is ported when **all** of these hold. The report (section "Evidence and report") has one line per
item with the evidence.

- [ ] D1. `entrypoints.emtk` in the manifest points at a factory `make_app()` that
      returns an `ImApp`, built **without importing Qt or `chisurf.gui`** (proved by the
      tool's `qt_free` check).
- [ ] D2. Every control the Qt window had is present in the emtk app, or is listed in
      the report's "Deliberate differences" table with a reason (`compare.json`
      `lost` list is fully explained).
- [ ] D3. Every interactive control has a tooltip (`after.json`
      `controls_without_tooltip` is `[]`).
- [ ] D4. The app draws without error at 1200×800 **and** 800×600, in the empty state
      **and** in a realistic populated state (real test data loaded, the main action
      run). Screenshots of all four exist and you have looked at each.
- [ ] D5. The main workflow works: a test drives the model (and where practical the
      app) from input to the same numerical result the Qt tool gave.
- [ ] D6. Persistence: whatever the Qt tool remembered (last folder, settings keys),
      the emtk app remembers, through `export_settings()` / `restore_settings(dict)`.
- [ ] D7. `gui/guide.json` steps point at controls that exist in the emtk app and
      wait for the user; `gui/help.md` exists and its links are live.
- [ ] D8. Docs updated (section "Docs").
- [ ] D9. The plugin's full test folder is green (output pasted in the report).
- [ ] D10. The report is complete, the evidence files are committed, the agent board
      entry is updated.

Always the project's Python and these variables (macOS, this machine):

```bash

export QT_QPA_PLATFORM=offscreen
export PYTHONPATH="$PWD:$HOME/dev/emtk"
PY=~/mambaforge/envs/arm64/bin/python        # never the conda base env
```

`emtk` lives in `~/dev/emtk` (a separate repository). You **read** it; you do not edit it.

| Purpose | Command |
|---|---|
| Capture the Qt "before" | `$PY -m test.gui.emtk_port_parity before <id> --out okf/plugins/emtk-ports/<id>` |
| Capture the emtk "after" | `$PY -m test.gui.emtk_port_parity after <id> --out okf/plugins/emtk-ports/<id>` |
| Measure the diff | `$PY -m test.gui.emtk_port_parity compare <id> --out okf/plugins/emtk-ports/<id>` (exit 0 = clean) |
| Plugin tests | `$PY -m pytest chisurf/plugins/<group>/<id> -q -p no:cacheprovider` |
| Tool self-test | `$PY -m pytest test/gui/test_emtk_port_parity.py -q -p no:cacheprovider` |

`<id>` is the manifest `id` (for example `pch`), not the folder name — they
usually match; check the manifest.

**Two traps that produced false results in the past audit — read them:**

* Draw an app with `app.draw(painter, 0, 0, w, h)`, **never** `app.gui()`. Hub apps
  choose their child window inside `draw`; `gui()` shows a bogus "panel pending" page.
* Judge a screenshot from the **full-size PNG**. Down-scaled contact sheets with
  labels and crops invented three "overlaps" and "clipped text" that did not exist.

# The reference port

`chisurf/plugins/core/f_test/` is the structure to imitate (files: `gui/app.py`,
`gui/ftest.view.json`, `gui/model.py`, `gui/guide.json`, `gui/help.md`,
`test/test_native.py`). It draws its forms with `emtk.view_form.draw_form`, builds a
`DockManager` for two windows, and its test file shows the four tests you must write.
It has two blemishes you must **not** copy: it patches guide text from Python (edit
`guide.json` instead) and it hand-draws its toolbar buttons (fine, but keep them in one
small method). Run the tool on it to see what clean evidence looks like:
`$PY -m test.gui.emtk_port_parity after f_test --out /tmp/f_test_evidence`.

# Choose the port type (do this first, write it in the report)

Open the plugin folder and its manifest.

* **Type A — adapter.** `gui/app.py` already exists and draws with emtk, but the class
  used by the menu is a Qt class in `gui/tool.py` that creates the app (`ControlHost`)
  and gives it Qt objects (`MfdPrepareApp(self, ...)` receives the Qt tool). Work: make
  the app stand alone. Procedure: the "Type A" section below.
* **Type B — Qt only.** No emtk app; the UI is Qt (often `AutoForm` + `view.json`, or
  hand-written widgets). Work: write model + spec + app. Procedure: the "Type B" section below.
* **Type C — script entrypoint** (`entrypoints.script`, no `gui`). Audit only; see "Backlog, waves, and the pilot gate".

If it is not clearly A or B, stop and ask.

# The procedure (both types): gates in order

Do not start a step until the previous step's gate is satisfied. Every gate leaves a
file or an output pasted in the report.

## P0 — Claim and read
1. Read `okf/agent-board.md` (whole file) and append your claim.
2. Read the plugin's `README.md` (if any), `manifest.json`, `gui/help.md`, and all its
   tests. List in the report the controls the **user** sees (from the Qt code) — this is
   your checklist for D2. Use `grep -n "addWidget\|QPushButton\|QComboBox\|QCheckBox\|QLineEdit\|QSpinBox\|addAction\|QLabel" <qt files>`
   as a start, but the authority is the screenshot in P1.
3. **Gate P0:** claim posted; control checklist written.

## P1 — Capture the "before" (before you edit anything)
1. `git status --short -- chisurf/plugins/<group>/<id>` and paste it in the report
   ("state at start").
2. Run the `before` command. Open `before.png` with the Read tool and **look at it**.
   If it is blank, tiny, or shows an error dialog, the Qt tool needs data or a
   different construction: drive it into a realistic state in a small throwaway script
   (load the plugin's test data from its `test*/data` folder), save `before_populated.png`
   yourself with `widget.grab().save(...)`, and add the file to the evidence folder.
3. Compare `before.json` `controls` with your checklist; add anything missing to the
   checklist (menus, tabs, context menus, dialogs are controls too — open each tab and
   screenshot it: `before_tab_<name>.png`).
4. **Gate P1:** `before.png`, `before.json` (and populated/tab screenshots) exist and
   are committed **first, in their own commit** ("<id>: Qt baseline for the emtk port").
   Never change `before.*` afterwards.

## P2 — Model that does not need Qt
The model holds the state and does the work; the GUI only shows and edits it.
* If `gui/view_model.py` (or similar) exists and imports no Qt, reuse it unchanged.
* If the logic lives inside the Qt class, move it into a Qt-free class in
  `gui/model.py` **by cutting and pasting the methods, not rewriting them**. Keep names.
  The Qt tool keeps working by calling the same model (change its imports only).
* Heavy work (files, fits, correlations) must not run in the draw loop. Use
  `chisurf.emtk.jobs.SnapshotJob(model)`: `job.start("method_name", ...)` runs the
  named model method on a copy in a thread; call `job.poll()` once per frame; it copies
  the results back and calls `model.notify(...)`.
* **`gui/__init__.py` must not import Qt.** Many plugins have `gui/__init__.py` doing
  `from .tool import <QtTool>`; that makes `import ...gui.app` fail without Qt. Make the
  export lazy (PEP 562 `__getattr__`, as in `chisurf/plugins/pch/gui/__init__.py` and
  `core/f_test/gui/__init__.py`) so the Qt tool still imports by its old name.
* **Gate P2:** the model's tests (P6, tests 1–2) pass with no Qt imported.

## P3 — Spec
Write `gui/<name>.view.json` (if the Qt tool already has one, copy it and adapt).
Vocabulary that `emtk.view_form` draws (anything else is silently ignored — verify each
section you use appears in the screenshot):

| Section | Use for |
|---|---|
| `panel` (`title`, `n_col`, `collapsible`, `collapsed`, `sections`) | grouping; `n_col: 2` puts two fields per line |
| `value` (`attr`, `label`, `kind` int/float/str, `minimum`, `maximum`, `decimals`, `step`, `read_only`, `call`, `description`) | numbers, text |
| `value` + `"style": "slider"` | bounded parameters |
| `choice` (`attr`, `options` or `options_source`, `labels`, `call`, `description`) | dropdowns, radios |
| `toggle` (`attr`, `label`, `description`) | checkboxes |
| `button_row` (`buttons: [{action, label, description}]`) | actions; `action` names a **method** on the model, called with no arguments; `enabled(action)` on the model greys it |
| `table` / `custom` `data_table` (`source`, `columns`, `editable`, `selected_call`) | every table |
| `info` | read-only text |

Rules: every section has a **`description`** (it becomes the tooltip); labels have no
emoji; a field's `call` names a model method that recomputes what depends on it;
`hidden_when` hides a field. Spec keys are attributes of the model — misspelling one
does not raise, the field just shows nothing, so P7 enumerates them.
* **Gate P3:** a test loads the spec and asserts every `attr`/`call`/`action` exists on
  the model (test 3 in "Tests to write").

## P4 — App (Type B) / decouple (Type A)
The "Type A" or "Type B" section below gives the code. Common constraints:
* The class extends `emtk.app.ImApp`; the factory is `def make_app(): return <App>()`
  in `gui/app.py` (Type A: keep the existing factory name if the manifest already uses
  it). No Qt, no `chisurf.gui`, no module-level work at import.
* Files are chosen with `emtk.file_dialog.FileDialog` (see `psf_calculator/gui/app.py`
  lines ~83–100 and ~190–205 for the exact draw/return contract), not `QFileDialog`.
* Plots use `emtk.implot` (`begin_plot`, `plot_line`, `end_plot`); images use
  `chisurf/emtk/image_canvas.py`; region drawing `chisurf/emtk/regions.py`.
* **Gate P4:** `make_app()` returns; `app.draw(RecordingPainter(), 0, 0, 1200, 800)`
  runs three times without an exception (test 4).

## P5 — Guide, help, tooltips
* `gui/guide.json` (steps: `title`, `text`, `target`, optional `await`). Targets are
  control names: for spec fields the `attr`, for buttons the `action` name; hand-drawn
  controls register with `self.item_rects["name"] = im.get_item_rect()` right after
  drawing. Rewrite step text so it names the **emtk** controls (Qt-era text often says
  "press the toolbar button"). Each step that needs the user to do something has an
  `await` that waits for it; the tour never presses a button for the user.
* `gui/help.md`: keep the Qt help; links are `[title](docs/concepts/x.md)`.
* Wire both exactly like `f_test/gui/app.py`: `EmTkHelpWindow(...)`,
  `EmTkGuidedTour(steps=..., get_target_rect=..., owner=self, wait_for_controls=True)`,
  `form.on_used = tour.notify_used`, and draw `help_window` and `tour` last in `render`.

## P6 — Tests (section "Tests to write") — write them now, not at the end.

## P7 — Evidence: after
1. Run the `after` command. Read `after_1200x800.png` and `after_800x600.png`.
2. Drive the app into a populated state in a throwaway script (load test data, press the
   main action by calling the model/app method the button calls) and save
   `after_populated_1200x800.png` with `test.gui.emtk_port_parity.emtk_screenshot(app, path, (1200, 800))`.
   Read it. Fix layout problems and re-grab until none of these is visible: clipped
   labels, text running past its box, overlapping windows, an empty panel, a plot with no
   axes, a status box filling the panel.
3. Run `compare`. Exit code must be 0. A control present before and absent after is
   `lost`. For each one either find it (a rename you can see in the screenshot: then the
   inventory is wrong, say so in "Blocked") or record the deliberate difference in
   `okf/plugins/emtk-ports/<id>/deliberate.json` as `{"<control text>": "why, and what
   replaces it"}` (for example a table replacing stacked `ε 1`, `⟨N⟩ 1` rows) and re-run
   `compare`. The entries then show under `explained` in `compare.json` and must match
   the report's "Deliberate differences" table; `stale_explanations` must be empty.
   Never add a control to `deliberate.json` that you simply forgot to port.
4. **Gate P7:** `compare` exit 0; screenshots read; nothing clipped.

## P8 — Docs (section "Docs") and OKF
Also strike the plugin from the **shrinking allow-lists** that its new files satisfy, in the
same change: `test/plugin_help_guide_allowlist.txt` (once it ships `help.md` and
`guide.json`), and `test/prd_mention_allowlist.txt` if you touched a file listed there
(remove any `PRD-nn` mention from that file). Run `$PY -m pytest test/test_plugin_help_guide_seam.py -q -k <id>`
and `test/test_prd_mentions.py`; the stale-entry tests fail when you forget. Failures of
*other* plugins in those files are not yours: list them in the report, do not fix them.
## P9 — Switch the manifest (last code change)
Only now add `"emtk": "chisurf.plugins.<group>.<id>.gui.app:make_app"` to
`entrypoints` (Type A: it may already exist — then confirm it points to the
Qt-free app). Adding it makes the menu open the emtk version by default, so it must
come after every gate. Do **not** remove `entrypoints.gui`.
Run the whole plugin test folder and `test/gui/test_emtk_port_parity.py`.

## P10 — Report, board, commit
Fill `okf/plugins/emtk-ports/<id>/REPORT.md` from `okf/plugins/emtk-ports/_TEMPLATE.md`
(section "Evidence and report"). Update the board. Commit (section "Committing").

# Type A — decouple an existing emtk app from its Qt tool

Example: `chisurf/plugins/burst/mfd_prepare` (`gui/tool.py` = Qt `ChisurfDockTool` that
builds `MfdPrepareApp(self, on_browse=..., on_prepare=...)` and reads `tool._folder`,
`tool._report_text`).

1. Create `gui/model.py` with a Qt-free class holding what the Qt tool held (`folder`,
   `report_text`, `running`, ...) and the actions (`browse` → sets a flag that opens a
   `FileDialog`; `prepare()` → the code that was in `tool._prepare`, using the plugin's
   client / API exactly as before; heavy calls through `SnapshotJob`).
2. Change the app to take `model` instead of `tool`, and to own its `FileDialog` (draw
   it in `render`). Replace every `tool.<attr>` by `model.<attr>`. Remove the `WINDOW_BG`
   etc. constants and the `background=` argument users; use the default style.
3. Add `make_app()` to the app module. The Qt `tool.py` now builds the same app with the
   same model (`ControlHost(app)`), so the legacy window keeps working until the
   reviewer removes it.
4. Replace the app's hand-drawn form by `draw_form(spec, model, state)` where the fields
   are ordinary values/choices/toggles/buttons (write the spec per P3). Keep hand-drawn
   code only for plots and canvases.
5. Emoji and hardcoded-colour removal is part of the port (rules 5, 6).
6. Continue at P5.

# Type B — Qt-only plugin

Skeleton (adapt names; this is the exact structure to produce):

```python
"""Native emtk <Name> tool (form from <name>.view.json)."""
from __future__ import annotations

import json
from pathlib import Path

from emtk import im
from emtk.app import ImApp
from emtk.file_dialog import FileDialog
from emtk.view_form import FormState, draw_form

from chisurf.emtk.help_guide import EmTkGuidedTour, EmTkHelpWindow
from chisurf.emtk.jobs import SnapshotJob

from .model import <Name>Model

HERE = Path(__file__).parent


class <Name>App(ImApp):
    def __init__(self, model=None):
        self.model = model or <Name>Model()
        self.job = SnapshotJob(self.model)
        self.spec = json.loads((HERE / "<name>.view.json").read_text())
        self.form = FormState()
        self.dialog = None                       # a FileDialog while one is open
        self.item_rects = {}
        self.help_window = EmTkHelpWindow(
            title="<Name> — Help", resource=HERE / "help.md", owner=self)
        self.tour = EmTkGuidedTour(
            steps=HERE / "guide.json", owner=self, wait_for_controls=True,
            get_target_rect=lambda k: self.item_rects.get(k) or self.form.rects.get(k))
        self.form.on_used = self.tour.notify_used
        super().__init__(self.render, continuous=True)   # continuous: a job may be running

    # -- one frame ------------------------------------------------------ #
    def render(self):
        self.job.poll()
        vp = im.get_main_viewport()
        box = (*vp.pos, *vp.size)
        self._toolbar(box)
        self.form.rects.clear()
        if im.begin("<Name>", box):                      # or DockManager as in f_test
            draw_form(self.spec, self.model, self.form)
            self._results()                              # plots / images only
        im.end()
        self._dialog()
        self.help_window.draw(box)
        self.tour.draw(*vp.size)

    def _toolbar(self, box):                             # Help / Guide only
        ...
    def _results(self): ...
    def _dialog(self): ...

    # -- persistence ---------------------------------------------------- #
    def export_settings(self):  return {"folder": self.model.folder}
    def restore_settings(self, s): self.model.folder = str(s.get("folder", ""))

    def close(self): ...                                 # stop threads, close files


def make_app() -> <Name>App:
    return <Name>App()
```

Model contract for `draw_form`:
* spec `attr` → plain attribute (`setattr` on edit); spec `call` → method called with
  the new value after the write; `button_row` `action` → method called with no
  arguments; optional `enabled(name) -> bool` and `bounds(name) -> (lo, hi)`.
* Do heavy work by `app.job.start("run")`, never inside `draw_form`'s call.
* `SnapshotJob` needs the model to have `notify(event)`; if the plugin already has a
  view-model base class with observers, keep it. Otherwise give the model
  `self._observers = []`, `add_observer(cb)` and `notify(event)` that calls each callback.

Tables: a `data_table` section reads a **source** attribute of the model (a list of
dicts or an array) and names its `columns`; do not write `im.begin_table` yourself.

# When to stop and ask

Stop, write the question in the report under "Blocked", update the board, and tell the
reviewer, if **any** of these happens. Do not work around it.

* A file you must edit has changes you did not make.
* The Qt tool cannot be constructed offscreen (needs a database, a device, a network).
* The spec vocabulary cannot express a control (a widget, a tree, a canvas interaction)
  — name the control and what it does.
* `emtk` lacks something (a widget, a key event, a file filter) or an emtk behaviour looks
  wrong (clipped text, a control that does not respond). Do **not** patch emtk. Record a
  minimal reproduction: a five-line script and the screenshot.
* A numerical result of the model differs from the Qt tool's.
* You would need to change the plugin's science, backend, RPC or manifest `rpc_methods`.
* A gate fails twice for reasons you do not understand.
* You have spent more than the plugin's estimated effort (Type A: 1 day; Type B small:
  3 days) without reaching P7.

# Things that look like bugs but are not (pilot findings)

* `⟨N⟩` looks like `(N)` at the default size: Menlo's angle brackets are shallow. Keep
  the correct character in labels; do not substitute `<N>` and do not report it.
* The parity recorder lists buttons and spec fields, not table columns or plot contents;
  a table replacing stacked rows is a `deliberate.json` entry, not a lost control.
* A Qt tool that saved PNG grabs can keep that part of Save: `from emtk.export import save_png`
  (`save_png(app, path, size=(1200, 800))`) writes the whole app window headless. It is the
  window, not one plot; a single-plot export is still an emtk feature request (write it in
  "Deliberate differences" and "Blocked"; do not add it yourself).

# Common mistakes seen in earlier ports (avoid all)

* Drawing the form by hand (`im.text` + `same_line(175)` + `drag_float` per field) instead
  of a spec — the tooltips, labels and layout then differ from every other tool.
* `im.text_wrapped(html_string)`: HTML shows as `<h4>` text. Use `im.markdown`.
* A hub or factory that does not accept an argument its parent passes (`coordinator=`),
  so the child never opens: test `make_app()` **and** the way the parent opens it.
* Guide text from the Qt era ("press the toolbar button 📊 From fit") that names a control
  that no longer exists.
* Tests that only check the window constructs.
* Editing the baseline images or `before.json` after the port started.
* Committing another agent's uncommitted work with yours.
