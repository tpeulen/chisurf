# GopichSzabo stops rebuilding

# Why

Phase-5 row, and the purest example of the crossing rule: the arithmetic
is already engine-side, but the *object* is rebuilt per likelihood
evaluation — construction cost and a numpy eigendecomposition guard paid
once per iteration of a scipy loop. Wrapping that loop in C++ would be
the measured 0.99× regression; the fix is persistence plus moving the
loop's owner.

# The job

1. Persist the engine object across likelihood evaluations; rebuild only
   when the *scheme structure* changes (rate values are updates, not
   rebuilds — the `assign_pda_histogram_function` cache keyed on what
   actually invalidates is the template).
2. Delete the redundant eigendecomposition guard — but first find what it
   was guarding (a silent `try/except` around a degenerate scheme?) and
   keep the *refusal*, loud, if the case is real.
3. Move `fit()` onto `bff.Minimizer` via the existing objective surface;
   likelihood objective, so `objective_type` must say so (the BUG-10
   likelihood-ratio threshold work is the precedent).
4. Measure per-evaluation cost before/after; the rebuild is the number to
   report.

# Definition of done

- [ ] Zero engine constructions inside the likelihood loop (counted, the
      way the zero-update_model pins count).
- [ ] Fit answers unchanged on the reference dataset; timing reported.
- [ ] The guard's real case (if any) refuses loudly instead of silently
      recomputing.
- [ ] Phase-5 row struck in [PRD-105](prd-105.md).
