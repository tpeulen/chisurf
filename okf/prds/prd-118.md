# FcsMdf node — the MDF diffusion mode fits through the graph

# Verification (2026-09-03, review pass)

Landed by `e99d9372b`/`6ab414e64` (imp.bff `536398e`), audited and repaired:

- **Defect found and fixed in review: the producer's ports opened at
  `build_ports()` defaults, not the model's values.** A *fixed* non-default
  `w0`/`wem`/`diam` left the graph computing a different instrument —
  measured 50% relative error — while every "builds and runs" assertion
  passed. `_fcs_mdf_producer` now writes the model's values at build
  (mirroring the kinetics producer, which always did), and the vacuous
  "builds or refuses" test was replaced by a real curve pin at 1e-12 with
  non-default fixed physicals plus a live-chain check
  (`test_mdf_mode_takes_the_graph_and_the_curve_is_the_python_curve`).
- Producer-port writes propagate through `chi2.update()` alone (verified —
  the Minimizer's call pattern re-evaluates the upstream node).
- Measured after the fix: mdf fit 2170 → 1818 ms (1.2x) — the kernel
  dominates, as this PRD predicted; the crossing was not the cost here.


# Why

`GeneralFCSModel` fits through the graph in its three closed-form modes
(PRD-105 phase 3); the `"mdf"` mode refuses because `enderlein.g_diff` is a
numerical kernel (`IMP.bff` `FcsMdf`, ported 2026-09-02 at 110 → 5.3
ms/curve), and a kernel is not an expression. The refusal is recorded as
deliberate in
[graph-eligibility-verdicts](../references/graph-eligibility-verdicts.md);
this PRD is the follow-through.

# The job

1. Add an `IMP.bff.FcsMdfCurve` node (name open): ports for `N`, `D`, `w0`,
   `wem`, `b`, `bg`, `diam`; optics configuration set once
   (`MdfOptics.as_optics()` values are fixed calibration); the tau axis set
   once from the data; `evaluate()` calls the existing `fcs_mdf_g_diff`
   kernel and composes `b + amplitude * g`, exactly as
   `GeneralFCSModel._update_model_inner` does.
2. The bunching/anticorrelation factors and the count-rate background
   factor stay an `Expression` *downstream* of the node (multiply the
   node's output port) — do not re-implement them in C++; the composition
   already exists and is tested.
3. In `_member_objective`/`_single_objective`, teach the builder the
   producer-node pattern the decay path already uses (`_spectrum_chain` is
   the precedent): a model may declare a curve-producing node in front of
   its expression.
4. Wire `GeneralFCSModel` (`"mdf"` mode) and `MdfFCSModel` to it.

# Definition of done

- [x] Node curve == `update_model` at 1e-10 with relaxation terms armed
      (census-style parity; the derived outputs Veff/conc/tauD stay
      display-side writes).
- [x] Freeing an optics parameter (fixed calibration folded into the node)
      refuses the graph via the unclaimable-port rule.
- [x] Census: `GeneralFCSModel` "mdf" and `MdfFCSModel` flip to yes.
- [x] Before/after fit timing reported: 2170 → 1818 ms (1.2x) — the
      kernel dominates; the crossing was not the cost here.

# Traps

- The kernel caches its quadrature on grids (`hermgauss`); build the node
  so the cache survives across evaluations, or the graph is slower than
  the director (measure, per the standing rule).
- `set_output_parameter` writes round-trip through the API and re-enter
  `update_model` — the node must not trigger them; leave them to the
  post-run display refresh.
