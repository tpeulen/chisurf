# Census hardening — a curve that was never computed must not read as buildable

# Why

The census's dangerous rows are its **silent passes**, recorded in
[graph-eligibility-verdicts](../references/graph-eligibility-verdicts.md):
on a fixture without its payload `Mfd2DModel` constructs and `update_model`
no-ops, and `FidaModel` computes on a meaningless axis without complaint.
Both read as "buildable, just not built" when the truth is "never computed
at all" — and PRD-119's parity check would inherit exactly that hole.

# The job

1. `imp.bff/test/minimizer/census_models.py`: third column — after
   `update_model()`, is `model.y` non-degenerate (finite, non-constant,
   right length)? Print `dead` when it is not; a `yes` in the graph column
   beside a `dead` curve is the phantom this exists to expose.
2. `FidaModel`: refuse a non-integer / non-count axis outright (the model
   knows what a PCH axis is) instead of computing nonsense.
3. `pch_mixture`: file the upstream tttrlib bug its chisurf wrapper
   documents, per the standing rule (library bugs go upstream, the
   fallback WARNs naming the bug).
4. `Mfd2DModel`: make the no-op loud (raise or `logging.warning` naming
   the missing payload) — the census then reports it honestly.

# Definition of done

- [x] Census output carries the curve column; `Mfd2DModel` and `FidaModel`
      rows read honestly (`dead`/refusal, not `no`). Verified by running the
      census against this worktree: both rows show `dead` in the new curve
      column, each preceded by a named warning
      (`Mfd2DModel.update_model: no MFD burst payload...` /
      `FIDA: refusing to fit -- photon-count axis must be...`), and the
      `DEAD CURVES` summary line lists both.
- [x] A guardrail test pins the FIDA axis refusal
      (`test/models/test_fida_axis_refusal.py`, 3 cases: decay-shaped axis,
      gapped-integer axis, and the genuine `0..k_max` article that must still
      compute). `test/models/test_mfd2d_no_payload_refusal.py` pins the
      `Mfd2DModel` side the same way.
- [x] `pch_mixture`'s upstream bug turned out to be **already fixed** in
      tttrlib (`okf/BUGS.md`, fixed 2026-08-10, before this PRD was written)
      and confirmed present in the `arm64` env this repo actually runs in —
      no new filing was needed. The chisurf wrapper
      (`chisurf/core/models/pch/pch.py::pch_mixture`) documented it as "filed,
      awaiting a fix"; that docstring now says it is fixed and why the
      wrapper's own length check is kept anyway (defense in depth). Recorded
      in `okf/references/known-issues.md`. `FidaModel` does not go through
      `pch_mixture` at all (it uses the pure-Python `fida.fida_pch` path), so
      this item was never blocking its axis-refusal fix above.
- [x] The verdicts file's "what the census fixture hides" section updated
      to past tense (now "What the census fixture hid",
      `okf/references/graph-eligibility-verdicts.md`).

## Incidental fixes (found while getting the census runnable)

The worktree this PRD was implemented in was branched from an older `chisurf`
commit; bringing it to `development`'s tip surfaced three pre-existing,
already-committed breakages unrelated to this PRD's scope, each blocking
`import chisurf.core.fitting.fit` (and so the census script itself, and most
of `test/fitting/`) outright. Fixed on sight per the project's "fix breakage
the moment you find it" rule, each a small, self-contained, root-cause fix:

- `chisurf/core/graph/` (a 5-file, ~1600-line graph-theory package
  `factorgraph.py` has imported since commit `28ffe225d`) was never
  `git add`-ed in any commit (`git log --all --diff-filter=A -- 'chisurf/core/graph/*'`
  returns nothing) — only present, untracked, in one working checkout.
  Restored verbatim (byte-identical to the untracked copy, itself identical to
  the already-tracked `modules/chinet/chinet/graph/`) and committed.
- `chisurf/core/math/optimization/__init__.py` imported `leastsqbound` from
  its submodule but never re-exported `OptimizationCancelled`, which
  `chisurf/core/fitting/minimizer.py` imports from the *package* — added the
  missing re-export.
- `chisurf/core/parameter.py`'s frozen-parameter fast path unpacked 5 values
  from the 6-tuple `factorgraph.py` actually freezes (`is_linked, callable,
  bounds_on, lb, ub, fixed`), raising `ValueError` on every parameter read
  during any fit or sampling run — the majority cause of ~300 failures across
  `test/fitting/`. Fixed the unpack and wired the now-available frozen
  `fixed` flag into the one branch that had been reading `self.fixed` live
  (defeating part of the caching this code path exists for).
