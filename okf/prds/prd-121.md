# Census hardening — a curve that was never computed must not read as buildable

# Why

The census's dangerous rows are its **silent passes**, recorded in
[graph-eligibility-verdicts](../references/graph-eligibility-verdicts.md):
on a fixture without its payload `Mfd2DModel` constructs and `update_model`
no-ops, and `FidaModel` computes on a meaningless axis without complaint.
Both read as "buildable, just not built" when the truth is "never computed
at all" — and PRD-119's parity check would inherit exactly that hole.

# The job

1. `imp.bff/test/minimizer/census_models.py`: third column — after
   `update_model()`, is `model.y` non-degenerate (finite, non-constant,
   right length)? Print `dead` when it is not; a `yes` in the graph column
   beside a `dead` curve is the phantom this exists to expose.
2. `FidaModel`: refuse a non-integer / non-count axis outright (the model
   knows what a PCH axis is) instead of computing nonsense.
3. `pch_mixture`: file the upstream tttrlib bug its chisurf wrapper
   documents, per the standing rule (library bugs go upstream, the
   fallback WARNs naming the bug).
4. `Mfd2DModel`: make the no-op loud (raise or `logging.warning` naming
   the missing payload) — the census then reports it honestly.

# Definition of done

- [ ] Census output carries the curve column; `Mfd2DModel` and `FidaModel`
      rows read honestly (`dead`/refusal, not `no`).
- [ ] A guardrail test pins the FIDA axis refusal.
- [ ] tttrlib issue filed for `pch_mixture`; wrapper's fallback warns with
      the issue reference.
- [ ] The verdicts file's "what the census fixture hides" section updated
      to past tense.
