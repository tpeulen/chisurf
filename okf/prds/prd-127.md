# PDA algebra dedup

# Why

Phase-4 register row. The sharpest case is `pch/pch.convolve_pch`: a
Python self-convolution *in the same file* as the `tttrlib.pch_*` calls —
the two-implementations-in-one-file shape that disagrees silently.
`mfd/histogram.py` re-implements binomial/Poisson PDA beside
`tttrlib.Pda`; `pda3c/likelihood.burst_log_likelihood_reference`
duplicates `PdaBurstLikelihood`.

# The job

1. Per copy, decide *forwarder* or *frozen reference*: a reference used
   only by a parity test moves into `test/` with the frozen-reference
   naming (the `_quickfit_reference` transcription in
   `test/models/test_fcs_maxent_engine.py` is the template); a live path
   forwards.
2. Parity A/B before each change — PDA is where the S1S2 cache defect hid
   (6× per residual, found 2026-09-02); assert on realistic n_max, not
   toy sizes.
3. `burst_log_likelihood_reference`: if it is already test-only, this row
   is a *move and rename*, not a port — check callers first.

# Resolution (2026-09-02)

All three named copies verified against their actual callers (not assumed):

- **`pch/pch.convolve_pch`** had zero production callers — `pch_model.py`
  and the plugin backend already go through `pch_mixture`/`pch_open_system`
  (both real forwarders to `tttrlib.pch_*`, pre-existing). Its only callers
  were its own tests. Moved to `chisurf/plugins/pch/tests/test_algorithms.py`
  as `_convolve_pch_reference`, frozen, following the `_quickfit_reference`
  template. Its own docstring already said why it was never actually a
  tttrlib duplicate: tttrlib keeps its self-convolution file-static inside
  `pch_open_system` (Poisson-averaged occupancy) and exposes no entry point
  for the *closed*-system (exact-`n`) case this computes — it was orphaned,
  not wrong.
- **`pda3c/likelihood.burst_log_likelihood_reference`** was already
  test-only (`burst_log_likelihood` forwards to `tttrlib.PdaBurstLikelihood`
  since an earlier refactor, `8df21a249`). Per the job's item 3, this was a
  move-and-rename: relocated to `test/models/test_pda3c_likelihood.py` as
  `_burst_log_likelihood_reference`, all ~7 call sites (direct imports and
  `likelihood as L` attribute access) repointed, `test_the_numpy_implementation_is_gone`
  extended to assert the name is gone from the module.
- **`mfd/histogram.py`'s `acceptor_count_distribution(s)`** turned out, on
  inspection, **not to duplicate `tttrlib.Pda`**: `tttrlib.Pda` computes a
  global S1S2 histogram from one fixed `(background_ch1, background_ch2, pF)`
  triple, while this function is conditioned *per burst* on that burst's own
  signal count and its own green/red observation spans (`okf/references/mfd-forward-model-alternatives.md`
  records why the 2D-MFD forward model needed this generalisation — the burst
  span itself, tried as the averaging window, cost 18-33% bias). There is no
  engine entry point at this granularity, and constructing a `tttrlib.Pda`
  object per burst-conditioned cell (thousands per fit evaluation) would
  reintroduce the class of cost the module's own vectorisation exists to
  avoid. Left in place, undocumented claim in this PRD's own "Why" corrected
  here rather than forced into a mismatched forwarding.
- The **S1S2 cache defect** (`2c3930b11`, `pda2c/common.py`
  `assign_pda_histogram_function`) lives entirely outside this PRD's three
  files (pda3c uses `PdaBurstLikelihood`, not the cached `tttrlib.Pda`
  callback) and was re-verified intact and untouched.
- Two of the three files (`pda3c/__init__.py`, `pda3c/likelihood.py`) also
  carried a PRD-65 in-source mention (`test/prd_mention_allowlist.txt`);
  touching them triggered the "a file you touch is a file you clean" rule —
  dropped (no owning OKF concept existed to point at instead) and struck
  from the allowlist.

      not ship at this granularity — verified, not a violation.)

      `k_max` to 400 — and remain so after the move; 29/29 and 11/11 tests
      pass).
- [x] Register row struck in [PRD-105](prd-105.md).
