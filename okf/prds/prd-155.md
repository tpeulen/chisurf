## Part A -- fret_check (from smfret-web)

### W-A1 Control inventory and plugin skeleton

- Inventory smfret-web first (no lost functionality): detection (cw, PIE any order/gap/period,
  usALEX micro+macro, MFD 0/8 1/9, noise channels, one-colour), QC verdicts (burst rate and
  density, P(multi-molecule) two ways, short-gap excess, concentration advice, brightness,
  S/B, background, stability, outliers, DO/AO, 2CDE), the docked UI (simple + advanced), the
  burst table, ndX hand-off, help + tour, export CSV/JSON, the web worker jobs with progress
  and cancel. This list is the acceptance baseline for the migration.
- `chisurf/plugins/burst/fret_check/`: manifest (id `fret_check`, display
  `Spectroscopy:Single-Molecule:FRET check`), `entrypoints.emtk` = the app factory from
  `smfretweb.app.frame:make_app`, `rpc_methods` = detect/analyse/qc job JSON schemas.
- The single-button contract: the plugin opens as one drop-zone button and a verdict;
  advanced mode behind a toggle, exactly the site's simple/advanced split.

### W-A2 Core port, interop, tests

- Port `smfretweb` (detect, pipeline, qc, jobs, app) into the plugin; the vendored snapshot
  logic (`tools/vendor_deps.sh`) dies -- chisurf already ships ndX, core and mmfdb config to
  the page, so the bundle picks the plugin up automatically (`?app=fret_check`).
- Session interop (from the M3 sketch): "open the TTTR file loaded in ChiSurf"; "send bursts
  to burst analysis / ndX" in memory as a `tttrlib.DataStore`.
- Port the CI suite into the chisurf tree: detection simulations (the seeded cw/PIE/usALEX/
  MFD/noise/one-colour matrix), the app tests, the ndX tests -- they must run in chisurf's
  `test` env and inside the web closure test. A Load-example button with the seeded demo
  measurement (PRD-154 pickup 8 rule).
- Acceptance: every control from the W-A1 inventory answers in the plugin; the chisurf web
  page offers fret_check and it builds, draws and closes (the plugin sweep protocol); the
  verdict numbers match the standalone site on the cal1 usALEX and BH cw MFD fixtures.

### W-A3 smfret-web marked integrated

- smfret-web README: "integrated into ChiSurf as fret_check (PRD-155)" with the commit range;
  the site gets a banner pointing at the chisurf page; the repo goes into maintenance-only
  mode (security fixes) until the chisurf page is announced, then archived. Deploy plumbing
  stays private. peulen.xyz/smfret keeps serving during the transition.

## Part B -- the Labelizer (from ~/dev/labelizer)

### W-B1 Inventory and skeleton

- Inventory: scores (IMP.bff DSSP, surface depth, P(labelled|site) tables, pair score,
  accessible volumes), the AutoForm `view.json` panel, the chimol viewer, one/two-conformation
  ranking, conservation (endpoint / ColabFold / file), export. Acceptance baseline.
- `chisurf/plugins/modelling/labelizer/` (rename later if the owner picks `labelizer_ng`):
  manifest + entrypoints; the chimol plugin host pattern is the precedent (`chisurf/plugins/chimol/`).
- IMP.bff is already a chisurf dependency (native in pixi, pyodide wheel for the page) and
  chimol is already a plugin -- the Labelizer lands on existing rails.

### W-B2 Port, tests, example data

- Port core + app; the conservation endpoint stays optional and external (the chisurf plugin
  offers file/ColabFold paths; no new server dependency inside chisurf).
- Tests: seeded structures (the repo's fixtures), score determinism, the panel drawing; a
  Load-example button (a small PDB + pre-computed conservation file ship with the plugin).
- Acceptance: plugin sweep green on desktop and the page (the pyodide IMP.bff wheel already
  powers peulen.xyz/label, so the web path is proven); parity on the README's example output.

### W-B3 Standalone deprecated

- ~/dev/labelizer README: integrated into ChiSurf; site banner; maintenance-only, then
  archive. The conservation backend (labelizer-backend, the 25 GB UniRef search) stays as the
  one external service both the site and the plugin may call -- it is not part of chisurf.

## Part C -- shared

- Docs: `docs/reference/plugins/` pages for both (generator from a clean worktree), ribbon
  entries under the display names, i18n de/fr catalogue entries, ICON_SYSTEM.md vocabulary.
- OKF: log day entries per wave; this PRD's pickup list below; known-issues entries for
  anything found (status: lines, newest-first).
- The metadata editor (committed 97f573086) is the metadata surface both plugins use for
  their export metadata (flrCIF for fret_check bursts, deposit metadata for both).
