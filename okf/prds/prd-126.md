# Where to pick this up

Closed 2026-09-02. Everything in the job list below landed; nothing was left
unported. Two things worth knowing before touching this area again:

- **The module path in this PRD's own title/table was wrong.** `IMP.bff` has
  no `spectroscopy` submodule — every kappa2 function (`wobbling_kappa2`,
  `dipole_kappa_distance`, `wobbling_kappa2_distribution[_delta]`,
  `sample_kappa2_diffusion_with_traps`, `isotropic_kappa2_density`,
  `kappa2_isotropic`, `s2_delta_from_anisotropy`,
  `kappa2_distance_ratio_transform`, `kappa2_dipole_matrix`) lives flat on
  `IMP.bff` (see `include/OrientationFactor.h` / `src/OrientationFactor.cpp`
  in `imp.bff`, commits `ae7397e`/`fb5162f`, already landed before this
  session — someone else built the engine surface; this session ported
  chisurf's callers onto it). The two `general.py` forwarders
  (`kappa2_to_distance_ratio`, `convolve_distance_with_k2_ratio`) imported
  `from IMP.bff.spectroscopy.kappa2 import ...`, which raised `ImportError`
  on every call — dead on arrival, uncaught by any test. Fixed in the same
  change (see the log entry).
- **The engine's two Monte-Carlo samplers did not route through tttrlib's
  centralized RNG when this PRD started** — a local `std::mt19937_64` seeded
  per call. Fixed in `imp.bff` (commit `da571e3`): vendored a byte-identical
  copy of tttrlib's `Random.h` (kept in step by
  `test/photophysics/test_orientation_random_copy_is_identical.py`) and
  rewired `wobbling_kappa2_distribution` /
  `sample_kappa2_diffusion_with_traps` to draw through it. This is an
  `imp.bff`-side fix, in a separate repository/commit from the chisurf work.
- `kappasq_all_delta_new` (a second, unused, differently-parametrized grid
  sweep with an apparent bug in its own weighting — `weight_beta2 =
  np.sin(beta1)`, not `np.sin(beta2)`) had zero callers anywhere in the tree
  and no `IMP.bff` counterpart. Deleted rather than ported; see the log.

# Why

Phase-4 register row, already half-taken: two functions in
`anisotropy/kappa2.py` shim to `IMP.bff.spectroscopy.kappa2`, the other
~794 lines (scalar Monte-Carlo orientation loops) still compute in
Python. A half-forwarded file is the worst state — the seam exists, so a
divergence between the halves is invisible.

# The job

1. Inventory what the remaining lines compute (κ² distributions from
   orientation models, error propagation onto distances) and which bff
   `kappa2` entry each maps to; anything bff lacks goes *into bff first*
   (placement rule: orientation factors are coordinates-side).
2. Parity A/B per function — distribution moments and tails, not just
   means; the MC loops' RNG must go through the engine's central RNG
   (tttrlib `include/Random.h` precedent) so results are reproducible.
3. Forward, delete, keep the chisurf parameter/plot surface.

# Definition of done

- [x] No orientation Monte-Carlo arithmetic left in
      `anisotropy/kappa2.py`; the file is a surface. Every function
      (`kappasq`, `kappa_distance`, `kappa`, `calculate_kappa_distance`,
      `s2delta`, `p_isotropic_orientation_factor`, `kappasq_all`,
      `kappasq_all_delta`, `kappasq_dwt`) forwards to `IMP.bff`; the only
      Python left is seed derivation, flat-buffer reshaping and the
      per-frame trajectory loop (which does no orientation arithmetic of its
      own). `kappasq_all_delta_new` was dead code (no callers, no engine
      counterpart) and was deleted rather than ported.
- [x] Distribution parity pinned (moments + a KS-style tail check at
      fixed seed):
      `test/fluorescence/test_kappa2_engine_parity_ab.py` reproduces the
      pre-port Python inline (from git history) and compares it against the
      `IMP.bff` engine at matched sample count with `scipy.stats.ks_2samp`.
      Measured: `kappasq_all` at S²=(0.3, 0.5), N=20000 — mean 0.6679 (ref)
      vs 0.6633 (engine), std 0.1949 vs 0.1923, KS D=0.0147; at S²=(0.8, 0.8)
      — mean 0.6701 vs 0.6587, std 0.5033 vs 0.4971, KS D=0.0146. A same-
      distribution baseline (two engine draws, different seeds) sits at
      D≈0.01 for reference. `kappasq_dwt` at N=4000 — KS D<0.08. The existing
      `test/fitting/test_kappa2_distribution.py` (mean=2/3, widening with
      S², [0,4] bounds, bin-edge convention) also still passes unchanged.
- [x] Before/after timing (scalar Python MC loops are the classic 100×
      row — claim only what is measured). Measured, not assumed:
        - `kappasq_dwt` (was a genuine per-sample Python loop, 3 `kappasq`
          calls each): **~60x** faster (10 000 samples, warm import).
        - `kappasq_all_delta` (was already a numpy-vectorized, 32-row
          blocked sweep): **~1.9x** faster (step=0.25°, ~1.5M grid points).
        - `kappasq_all` (was already fully numpy-vectorized, not a loop):
          **no speedup** — engine and vectorized-numpy come out within
          ~10% of each other, engine occasionally slightly slower once SWIG
          marshaling is counted (200 000 samples, warm import, 5-run
          average). The "classic 100x row" describes the genuine scalar
          loops (`kappasq_dwt`, and the old `calculate_kappa_distance`
          per-frame arithmetic before an earlier port); it does not apply to
          functions that were already vectorized before this PRD.
