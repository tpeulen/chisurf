# The DEER bootstrap band through the graph

# Why

Found while dissolving the phase-3 "nested optimisers" item (2026-09-02):
`_DeerModelBase.compute_uncertainty` is a correct parametric bootstrap —
a re-fit per noisy replica is the method — but each of its ~120 re-fits
is a scipy LM in Python over the full kernel evaluation. The re-fit is a
*fit*, and fits have a graph route; the band is the last fit path in the
DEER family that crosses per iteration.

# The job

1. The replica re-fit holds nuisance parameters fixed and fits only the
   shape parameters against a synthetic target `v_b` — that is a
   graph-representable objective (same model, different data vector).
   Build one graph per band, swap the target per replica
   (`ChiSquared.set_data_arrays` per replica is once-per-fit, allowed),
   run 120 `Minimizer.run()`s.
2. Keep scipy as the fallback exactly as `graph_objective`'s refusal
   contract does everywhere else.
3. The Tikhonov model's `_pr_bootstrap` is a fast re-inversion, not a
   fit — out of scope; only the Gaussian and Rice parametric re-fits
   move.
4. Statistical parity, not point parity: same band at matched seed within
   Monte-Carlo tolerance (the sampler port's parity method is the
   template), and point parity of a single replica re-fit at fixed data.

# Definition of done

- [ ] `compute_uncertainty` runs its Gaussian/Rice replicas through the
      graph when it builds; band parity pinned statistically.
- [ ] Timing: whole-band before/after (120 × the per-fit ratio is the
      expectation; report the measured number).
- [ ] The opportunity note in [PRD-105](prd-105.md) phase 5 struck.
